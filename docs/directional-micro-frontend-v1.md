# FS05 方向微调的正式评分读取与导出

本批把 FS05-M03、FS05-M04 的独立应用规则接入既有统一报告读取器、逐卡页面及导出。原目录仍是 `manual_review`，原卡等级仍为空；只有 `automatic-formal-card-scoring-v1.0.0` 政策、精确应用规则版本和完整可计算来源同时成立，才显示应用正式评分。单独人工标注、保存的通过标志或旧无政策报告都不能授权评分。

三项条件保留各自含义：沿人工所标轴接近该帧可见球至少 0.03 躯干单位；双脚整窗运动路程最大值位于 0.03–0.5 躯干单位；髋位移与所标轴的一致比例至少 0.7。纵、横轴分别来自原图标记，不把图像数学垂线当作球场横向。可见球位置不等于预计击球点，小步与轴向一致也不证明合理距离、真实触地或技术等级。

读取器重新计算原窗六关节共同分母、旧归一化与局部完整躯干坐标的代数关系、固定躯干尺度及首尾中位数、两脚各区间速度和完整低速—运动—低速、沿轴位移、轴向目标距离变化和一致比例。观察脚必须具有完整周期，另一脚可以运动；没有套用 FS4 的另一脚相对静止门槛。算法复用的只是已有纯脚部阶段计算，未修改其阈值。

每个原帧必须具有一致的所选原轨迹、相机分段、完整工程选择段账本及实际 PTS。模型原绑定的选择段与 primary 选择段分别核验；模型处理帧号以原锚帧为基准递增，不强制处理帧编号等于原帧编号。顶层窗口、实例标注、计算证据与执行元数据中的文档摘要必须一致。读取器能检验保存证据内部的一致性与数值，不会宣称浏览器已重新解码媒体，亦不把没有签名的完整自洽替换当作可以密码学验证的原始来源。

真实回归来自 native run `e4204ec3-7d84-4a90-a961-9dad01b43c2e` 固定原帧 112–136，共 25 帧。它与 production run `0a3df3a3-2629-4dd5-80a1-54e4b11f7341` 使用相同视频，但姿态、四个原始文件及报告来源不同，不能互换。完整 API 响应来自后端提交 `94b2f77df8df17be0fecdedcf95076b0bfc8504f`，原响应 SHA-256 为 `0e33be175f972db405af2ad38bae16644451c346878dbd2c9ca6f0e394c8b3c9`，以无损 gzip fixture 保留所有 298 卡、187 实例及完整来源，不使用测试拼装 envelope。

该报告 7 卡、113 实例获得正式分，总分 56.70248775838838。新增两卡都是 C60：纵向接近值 −0.385033707576911，横向 −0.4490654929941905；两者双脚最大路径 0.30026233094030963，一致比例分别为 0.8522268009051799 和 0.9939536226575706。前端按同卡实例均值再等权平均，末位浮点差小于 1e-12。窗口和条件均未为取分移动。

页面在正式模式默认选择当前卡首个有分实例；用户显式选择的缺测实例仍显示缺测，历史模式顺序保持。正式来源备注说明客观局限，不再要求人工复核；原始 code、原来源记录及历史报告文案保留。局部预载仍只是辅助测量，没有新增评分条件时保持空分。

JSON 备份保留新应用版本、全原帧来源、三条件数值、执行元数据和原始限制 code；读取后再次校验。可读导出分别陈述接近、小幅路径和轴向一致。隐私过滤仅对两个新增路径长度字段的有限数值放行，字符串路径及无关私有字段继续过滤。

验证入口：`scripts/build_directional_micro_display_contract.py --check`；`scoring-demo-web/tests/directional-micro.test.mjs`。反例涵盖缺参考/目标、旧和新坐标不一致、原模型错绑、两种选择段混淆、整列分段账本被删、处理帧错位、轴/目标/原图副本冲突、相机剪切、周期不完整、阈值或保存分数篡改及完整备份往返。合成原点偏移只验证数学和时钟约束，不新增真实动作或视频数量。
