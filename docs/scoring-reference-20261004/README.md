## 原文究竟规定了什么

两份卡片逐项给出技术定义、识别点、所需点、计算方向性描述、A～E 的文字标准、不可评价条件，以及建议反馈。全部 298 项均保留了独立的 E 级与不可评价字段：有足够观测却没有发生某行为，和关键证据缺失无法评价，是两种情况。后一种情况不能变为 E 级、零分或扣分。

FS 的 34 项和 GS 的全部 248 项明确规定特定部位或核心关键点有效帧**低于 70%**不可评价。原文使用严格“小于”，但达到 70%也不表示其它条件已通过。这个 70%是有效证据门槛，不能解释为 70 分、C 级阈值或全视频平均姿态覆盖率。有效帧的具体置信度定义、分母、所需关节集合及事件时间窗仍需工程契约补齐。

发球文档 `VIS-SV:P0020 / T002.R003.C002` 给出“最佳抛球高度为此人身高的 1.8 倍左右”。这是约数参考，没有容差或分段分值。`VIS-SV:P0048 / T005.R003.C002` 将落地后持拍手侧腿抬起称为“加分项目”，但没有加多少分；不能自创 +5 分或把未抬腿当扣分。

FS01-M04 的踝距/髋宽等比例描述属于原文特征定义，需与代码里的身体尺度归一化分开。FS02-M04 与 FS09-M04 提及“超过阈值”“低于阈值持续若干帧”，没有规定阈值或帧数。卡片计算方式中的“+”连接特征和时序描述，没有提供量纲统一、归一化系数或加权求分公式。

五份视觉材料定义五类、24 种技术：底线 5、发球 1、接发 5、网前 3、步伐 10。它们没有新增 298 指标之外的正式评分编号。本核验为段落与分号子条款生成的 KP/C 定位编号仅用于审计，不能当作原文正式指标编号。

## 当前三种数值含义

| 路径 | 当前计算或返回 | 可向用户表达的含义 |
|---|---|---|
| 前端 `engine.ts` 演示模式 | 场景基分、文本加成、确定性 ID 扰动；四维按 40/25/20/15 合成；A/B/C/D 分界 90/80/70/60 | 人工演示分数；均不是七份 Word 规定或视频实测 |
| 前端 `engine.ts` 真实模式 | `score=null`、`grade=null`，根据证据覆盖判断 ready/partial/blocked | 证据预检结果；ready 不代表技术合格 |
| `technique_assessment.py` | 就绪度 = `round(100 × (0.7 × 必需覆盖最小值 + 0.3 × 增强覆盖平均值))`；技术分与正式等级仍为空 | 证据就绪度；工程规则，不是技术分或准确率 |
| `scoring.py` 正式指标路径 | 有效证据、F4、教练标定、独立测试、可信晋级和精确运行版本绑定后，按阈值/有序回归返回 A～E | 通过门槛后的指标级正式等级；本模块不返回统一百分制或扣分 |

演示的聚合也没有原文依据：事件内指标等权；每个模块内事件等权；GS/FS 按 70/30 合成。它没有独立的阶段权重。由于各 GS 事件的指标数不同，模块内“每个事件同权”和“每个指标同权”并不是同一算法。不能用 `100 - 演示分` 捏造动作缺陷扣分明细。

真实评级路径在特征缺失或质量失败时输出 `unavailable`，在缺少标定或生产授权时输出 `calibration_required`。后端支持的四切点阈值法及有序回归都要求另有标定资产；Word 的文字等级本身不是该资产。即使将来得到 A～E，也不能自动反解成 90/80/70/60 分。

## 优先处理的差异与未决事项

1. **GS 源内错项。** GS01-M10-04 的技术定义是下一节标题“GS-02 双手反手”（`CARD-GS:P2614`）。GS02-M01-01、GS02-M01-02 的名称与定义/关键项疑似互换（名称 `P2652/P2696`，定义 `P2662/P2706`）。两端 JSON 忠实复制了原文，因此“转录一致”不代表规则正确。这三项应保留原文并标注源规则待修订，不自动执行错误语义。
2. **GS 阶段边界缺失。** 20 个阶段的开始和结束标志在原文均为空，涉及 97 张卡；包括 GS02-M03～M10、GS03-M01～M10、GS04-M01～M02。不能仅靠有阶段 ID 就宣称事件已可切分。
3. **FS 测量语义未完全实现。** FS01-M02 原文需要变化量/连续性，当前中位数或峰值不完整等价；FS01-M04 原文归一化分母是髋宽，代码是身体尺度；FS01-M05 与 FS09-M05 的后续事件关联没有完整进入必需契约。13 项 F2 只意味着当前代理特征可测。
4. **旧计划与新契约不同步。** `metric-measurement-plans.json` 声明 `pose-wave-2026-08-21.8`，当前 v2 和 requirements 是 `2026-10-01.2`。旧 `metric-feasibility.json` 只有 6 项，新版 13 项；不能将几个文件合并解释成已覆盖更多正式评级。
5. **宏观阶段与细阶段不同。** 九月 GS 五阶段与八月卡片每种击球的十阶段并存；盯球还贯穿全程。原件没有正式替代声明，不能静默把十阶段平均压成五阶段。网前正反截击稳定调整、高压蓄力三处原文明示可以没有，当前阶段数组未表达可选性，缺少这些阶段不能扣分。
6. **证据门槛口径不同。** 原文 70%针对指标关节；前端 0.65/0.72、特征有效率 0.50、事件运动学覆盖 0.75均有不同目的。F2 测量可以保留作误差核验，不能因此宣称满足正式评价条件。
7. **版本、复用和方向待确认。** FS 文件名为“第二版”，正文为“第一版”；FS01 总表/详细起点措辞不同；FS02-M02 来球方向与外部目标方向不等价。部分 GS 复用项的所需点、状态和不可评价条件也不同于所称来源，必须逐项保留，不覆盖成同一条。
8. **GS 的身份连续性没有进入前端依赖数组。** 248 张卡原文均要求目标球员 track 稳定，但当前 GS `dependencies` 没有 `tracking`；前端预检只据该数组构造必需依赖。正式接入前需要独立执行同球员、事件内的身份门禁，不能把姿态覆盖高直接解释为证据齐全。

完整差异均以“原文位置 → 当前文件/字段 → 一致、不一致、未实现或需标定 → 建议”记录。这里的“不一致”可能是工程规则新增、转录后的语义变化或源内矛盾；不自动意味着可以删除现有保守评分门禁。

## 来源优先级与修订方式

建议按作用域处理，而非按日期决定所有规则的高低。原始 Word 字节和 SHA 决定该版本原文；五份视觉材料负责宏观动作与可观测边界，两份指标卡负责其正式 GS/FS 指标与文字等级；实现只说明已经做了什么，不能反过来成为原文依据。没有明确废止关系时两套阶段合同并列存在。

源内错误先保留并标记，不静默换名、换定义或补空白。未来经规则维护者确认的修订应发布新源版本与哈希；未来数值阈值、权重和扣分规则应标为新增规则，并附教练标定、独立测试及适用场景证据。本文是交接审计，不替代这些确认。

## 现在可以诚实实现的前端解释

可显示动作定义、每条原文依据、视频事件或候选的时间段、实测特征及单位、代理限制、缺少的证据、待标定原因，以及有明确作用域的证据覆盖/就绪度。可将原文 A～E 作为“标准说明”展开阅读，不能在没有合格标定结果时给用户授级。

一项结果应能回答：是哪次动作、哪条原文、需要哪些证据、当前测到什么、哪些部分不可评价、是否有合格标定资产。未拍摄某类技术应显示“未观测”；缺少关键点应显示“证据不足”；尚未实现与待标定应分别说明。技术分、正式等级和扣分保持空值，不以零补齐。

建议固定提示：“已完成动作与证据核验；当前原文尚未给出完整百分制量表，正式评分仍需逐指标标定。”发球抛球约数、可选动作和局部测量以参考说明呈现。不能把球/球拍检测覆盖当真实触球，把头部朝向当真实视线，或把二维髋中心、踝减速当真实重心、发力与足底接触。
