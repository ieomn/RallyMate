# FS05-M02 连续微调前端应用评分

浏览器读取统一 `card-execution-v1.0.0` 的正式评分报告，独立计算 FS05-M02 的两个应用条件：完整视觉运动片段数至少 2；双脚全窗路径的最大值处于 `[0.03, 0.5]` 固定躯干单位。原卡规则仍为 `manual_review`，新增应用规则不宣称已验证原卡定性技术等级。历史无正式政策的输入不因此升级为正式评分。

独立 reader 为 `scoring-demo-web/app/lib/micro-adjustment-cycles-evidence.ts`，阈值与版本由 `scripts/build_micro_cycle_display_contract.py` 从已提交后端生成。它验证人工窗口、完整原帧分母、逐帧实际 PTS、原轨迹身份、选人及相机分段、完整派生选人账本、源质量、模型原始绑定及独立模型 epoch；同时复算旧归一化和局部完整躯干归一化所对应的六个必要关节。模型 processed index 沿源帧差连续，不强制等于源帧绝对编号。浏览器验证来源副本、数据合同和算术，不能凭报告自行重新核验媒体像素或确认人工标注真值。

每只脚在全窗上按既有速度规则分段，再对每个运动段及其相邻低速段复算局部周期。每段至少 3 帧、80 毫秒，端点中位数至少使用 3 帧。完整性由原坐标和时钟计算，不接受保存的完成布尔值。全窗不必只有一个周期；首尾截断运动保留全部路径及失败原因。

片段按运动区间的正长度重叠传递合并。仅共享端点不合并；不完整运动可以连接两个重叠运动段，但自身不能使片段成为完整片段。片段包含至少一个完整脚部周期才计数。完整脚部周期数、完整片段数和窗口描述频率分别保存，频率不作为第三个条件，也不解释成真实触地步频。

统一报告保留 `input.micro_adjustment_cycle_execution` 和 `micro_adjustment_cycle_windows`。前端规范化后将执行来源放在同名顶层字段；若顶层和 input 同时存在则必须一致。每个 top window 必须唯一且与实例 `source_window_annotation`、完整窗口和原帧序列一致；原四个输入文件 SHA、文档 SHA、原视频解码验证状态也随备份保留。缺源或数值闭合失败清空分数，不将缺测记为零。完整可算但条件不满足可以得到 C 或 E。
