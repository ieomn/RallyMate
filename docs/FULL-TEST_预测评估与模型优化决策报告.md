## 3. 关键问题与风险判断

1. **球和球拍覆盖率/稳定性不足**
- 在 3 个视频中，球帧覆盖率均低于 0.87，且在室内远景视频最低到 0.2865，说明模型会丢失大量关键球状态帧。
- 球拍覆盖率在短视频中也有明显波动，远景/遮挡场景更不稳定。

2. **court 校准仍未形成“可量化指标”的闭环**
- 自动 court 目前主要给出区域检测，`court_calibrated_fraction = 0`，不能直接用于后续物理量（落点、距离、速度）的精确计算。
- 场地固定时，当前结果说明“静态校准策略是可行的”，但缺少统一的标准化校准参数管理与多机位版本化。

3. **还不能做“商业级评分准确率承诺”**
- 我们目前在输出“可运行的帧级观察数据”，但没有足够的人工标注真值作精度验证，无法对误检/漏检率给出统计可靠性。
- 没有完成模型训练/微调闭环，模型仍偏“通用基线”。

4. **缺口与已识别的产品化风险**
- 许可证风险：当前推理链路依赖 Ultralytics 官方实现，若商业闭环部署需确认商业许可策略。
- 工程链路风险：当前任务适配了演示和单机验证，还未完成标准化版本化部署（A/B、监控、回归测试、失败回退）。

## 4. 是否需要重新训练自己的网球专项模型？

结论：**需要，且建议“重训策略是微调，不是从零训起**。

推荐分层策略：

1. **目标检测与球拍检测（重点）**
- 不建议从零训练。
- 建议在 `yolo26n` 上做网球域微调，优先补强：
  - 复杂背景下的 tennis ball 回归与抑制误检
  - 球拍形态、握拍/拍身遮挡场景
  - 多尺度远景小目标

2. **姿态（Pose，重用 COCO17 的基线）**
- 不建议从零训练。
- 建议先微调已有姿态模型到网球动作分布：发球、接发、截击、底线、场上回合切换等常见动作片段。
- 仅当需要球拍握法角度、落点相关关节点的高置信度、或自定义关键点（手指/脚部细节）时，才做自定义骨骼结构扩展。

3. **Court 建议**
- 你的场景“固定场地”成立，当前阶段**不需要专门训练 court 检测模型**。
- 建议做每机位一次性“可复现的手工标定/参数化模板”，并做版本化管理；后续再补足自动 court 回归模型用于自助接入新场地。

## 5. 需要重新标注吗？

需要，但不是“全量从头起步”：

- 必要标注（推荐先做）：  
  - 检测：`player/ball/racket`，优先增加远景和弱光/高混杂场景。  
  - 姿态：重点动作段视频分帧标注（至少 3k~5k 个高质量人体实例）。  
- 建议采用“**先抽样+人工抽检+迭代补标**”：
  - 第一轮：3k~8k 检测样本（按场景分层）
  - 第二轮：基于误检热图补充难例
  - 第三轮：闭环评估后扩容到 20k~30k（若要稳定商用）

## 6. 商业化可部署方案建议（最终路线）

### 阶段 A：先把第一阶段打磨稳定（1~2 周）
- 使用现有模型跑全量视频线，建立统一 `frames.jsonl` 格式和异常报警阈值（空轨迹、置信度坍塌、FPS 波动）。
- 对接 court 手工校准参数管理（按机位版本化）。
- 输出：可视化回放、质量报告、失败样本回收集。

### 阶段 B：专项微调（2~4 周）
- 数据管线：按视频类型（室内/室外、远景/近景、多人/单人）分层采样。
- 检测模型微调 + Pose 微调。
- 产物：新权重、验证集指标（Precision/Recall/F1 + 球/拍追踪一致性指标）。

### 阶段 C：第二阶段/指标化接入（3~4 周）
- 先做 hit event 粗检逻辑、落点估计、击球节奏。
- 引入球场坐标变换与评分模块，输出可解释字段（球速、落点分区、回合节奏）。
- 用 A/B 对比基线模型版本，逐步上线上线验证。

### 阶段 D：商业化强化（持续）
- API 鉴权、限流、版本回滚、日志合规、故障隔离。
- 离线批处理 + 实时流式混合两条路径。
- 持续数据回流训练（每周小规模增量更新）。
