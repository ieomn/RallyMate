本轮把分辨率、时间轴、镜头运动和评分语义分别修正：

1. **统一几何尺度。** 关键点先恢复原图像素，再把 x、y 同时除以画面长边；不再在 x/宽、y/高的非等比例坐标中计算距离和角度。横竖屏及等比例缩放遵循同一计算契约；人工标注对照也走同一路径。缺画面尺寸、非法数值不猜测补齐。低分辨率丢失的细节无法通过归一化恢复，关键点置信度和缺测仍保留。
2. **使用源时间戳。** 逐帧读取解码时间，不再用平均 FPS 代替真实帧时刻。时间戳不可信时明确标记 fallback，并隔离对应动作窗口。回放从原视频按实际采样帧导出，保留变帧率间隔和末帧；导出失败会明确声明回放时间未保真。
3. **背景支持的二维相机补偿。** 排除人框后，用分布足够广的背景光流、双向一致性和 RANSAC 相似变换建立当前画面到参考画面的矩阵。身体和用于动作上下文的球使用同一参考系；球拍框关联继续在原图像素中完成。无法可靠补偿时断开分析窗口；参考编号单调递增，平滑、导数和特征不跨无效段或参考切换。此能力不是三维姿态、真实场地距离或透视校正。
4. **步伐候选使用局部时间窗口。** 运动阈值使用附近时间片和按真实间隔加权的统计，身体尺度也局部估计，减少无关片段长度和帧率对同一动作的影响。脚步事件仍是可复核候选，不等于真实步数、足底接触或击球次数。
5. **转体按可靠连续段测量。** 肩线、髋线、夹角和角速度使用补偿后的等尺度二维坐标；低置信点、镜头参考变化和时间缺口断段，不跨段展开或求导。结果声明坐标来源，保留覆盖和缺测原因。这些二维投影测量不能直接当作人体轴向转体角度或动力链质量。
6. **移除没有技术标定依据的合成分。** 旧证据总分由覆盖、置信度和重复性合成，与技术好坏不等价，且会受到缺失项与权重归一化影响。当前这些成分各自展示，所有技术总分/证据总分保持 null；页面展示实际测量和缺测原因。导入、Markdown/HTML 报告、JSON 备份及旧页面使用相同语义。旧坐标契约任务明确提示重新分析，不能用旧值与新值直接比较。
7. **球路显示和时序有效期。** 保留用户要求的跨 ID 300 ms 上限及方向余弦 0.7 门槛。球 tracker 按实际毫秒过期；画面只显示仍在有效期内的候选轨迹，可展示多个独立候选，不把最后一个检测强行认作唯一真球。低置信/插值段分别提示，旧轨迹不无限停留。修复的是候选关联和显示逻辑，未验证球检测准确率。

## 4. 击球计数问题的当前结论

**当前完整链路没有接入经验证的球拍触球事件检测器，因此不应期待可靠击球总数。能检测到球、球拍、挥拍或发球动作，都不等于确认发生触球。**

证据链：

1. [pipeline.py:1059](C:/Users/Admin/Documents/网球/src/rallymate_vision/pipeline.py:1059) 明确输出 `hit_event_detector_enabled: False`。这不是只需改为 `True` 的开关；上游还缺触球判定、事件去重和证据验证。
2. [stroke_candidates.py:341](C:/Users/Admin/Documents/网球/src/rallymate_scoring/stroke_candidates.py:341) 输出 `confirmed_contact_count: None`，并声明候选不是击球次数。候选识别入口是 `detect_stroke_candidates`，读取产物的包装入口是 350 行 `recognize_strokes_from_artifacts`。
3. [stroke_analysis.py:225](C:/Users/Admin/Documents/网球/src/rallymate_scoring/stroke_analysis.py:225) 的动作片段仍为 `contact_confirmed: False`。准备、加速、随挥时间以及运动峰值不是触球时刻。
4. [user_demo.py:113](C:/Users/Admin/Documents/网球/src/rallymate_service/user_demo.py:113) 的 `_post_analysis_capabilities` 有意输出 `total_count`、`shot_count`、`contact_count` 为 `None`；有候选时状态为 `candidates_only`，否则为 `unsupported`。GS 事件计数保留在单独字段，不能变成击球数。
5. [live-stats.ts:59](C:/Users/Admin/Documents/网球/scoring-demo-web/app/lib/live-stats.ts:59) 的 `summarizeLiveStats` 只接受 `status === "observed"` 且 `count_semantics === "confirmed_contact_events"` 的有效总数；[LiveResults.tsx:68](C:/Users/Admin/Documents/网球/scoring-demo-web/app/LiveResults.tsx:68) 才显示已确认触球卡片，否则明确隐藏。

以下数量必须分开：

- 球检测点数：多帧中检测到球的观测数量。
- 球轨迹点数：轨迹预览或重建的采样数量。
- 动作片段数：例如 FS01/FS02/FS09 的事件段数，不是脚步数，也不是击球数。
- 挥拍/发球候选数：可人工复核的动作时间区间。
- 确认触球数：只有独立事件检测器输出经过约定验证的触球事件后才可统计。

`None`/`null` 表示不可提供，不是检测结果为零。不要通过把空值改成零、递归寻找任意 `hit_count`、将每个候选算一次、用球的轨迹拐点直接计数、删除前端门槛等方式“修复”显示。

基础证据也存在限制：本次球只在 47.67% 的帧中有观测，球拍主要是通用检测框，缺少拍头/拍面关键点与经过验证的持拍人关联，场地检测关闭。后续触球判定需要处理触球前后漏球、遮挡、轨迹断裂与主体关联，不能仅靠修改一个置信度阈值完成。

另外，当前前端“动作片段 21”来自 `result.actions` 的脚步事件计数，不包括另外的 2 段发球候选。虽然旁边标了“非击球次数”，名称仍容易误解；后续可改为“步伐事件片段”并分别展示运动分析与触球统计。本轮只记录问题，没有修改该 UI 或识别算法。
