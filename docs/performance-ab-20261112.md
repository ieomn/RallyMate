# 同视频性能对照与 Mesh 时间基修复

2026 年 11 月 12 日，对“长视频摘要优先与多 GPU 并发优化”对话使用的同一段视频完成了旧版与性能分支的顺序对照。本次完整分析耗时从 649.216 秒降至 639.877 秒，减少 9.339 秒、约 1.44%；SAM 姿态阶段仅减少 0.482 秒、约 0.13%。这段视频没有出现明显的模型推理加速。

测试在同一台 RTX 5070 Ti 机器进行。两版分别从固定 Git 提交导出源码、启动全新后端进程，模型加载并达到 ready 后，通过同一个本地前端上传入口各运行一次完整视频。首次任务包含实际发生的 CUDA Graph 捕获；模型加载与进程启动不计入下面的分析耗时。前端使用 8000 端口，API 使用 8001 端口。

源码、运行进程的白名单环境、模型身份、请求参数和源视频绑定均已核对。两轮均保留 13,116 帧、1,640 次 adapter 帧批调用和 531 个实际观察到的 IPC 请求。其余帧批没有可送入 SAM 的主体；1,640 次调用不能全部解释为 GPU 请求。

阶段墙钟包含相互重叠的工作，不能相加为总耗时。HTTP 可读时间采用相同的 3 秒轮询。该结果来自每版一次完整运行；历史同视频旧任务的流水线耗时为 648.835 秒，与本次旧版相近。优化版 `inference_ms` 排除了后台首次 Mesh writer 的最终等待，本报告没有用它与旧版直接比较。

这段视频两轮的原帧峰值都为 10,321,920 bytes，实际缓冲预算都为 64 MiB，最大批次都为 8 帧。B 的 1,639 批为 8 帧，末批为 4 帧，帧批填充率约 99.97%。高分辨率源帧预算扩容没有在本视频中触发。两轮 native 的主体分组、forward calls、IPC request ID 和首次模型调用标记一致。

缓存复用改变了资源保留情况，但本次 SAM 阶段的墙钟没有相应明显缩短。

三维回放暴露了一处功能问题。B 完成 219 个分段后，最终拼接未通过完整 PTS 校验，原始交付记录为失败。A 的上传至三维视频可播放时间为 697.869 秒；B 没有成功完成这一原始交付节点，因此不提供两者的 Mesh 完成时间比值。

根因是 `add_stream_from_template()` 没有显式继承分段容器的时间基。真实 NVENC 分段使用 `1/90000`，新 MP4 被选择为 `1/15002`，造成精细时间戳舍入。修复提交 `14803cbe3a0f5c3238f18cc52c74825a23df8030` 在创建输出 stream 后显式设置 `output_stream.time_base = stream.time_base`，保留原有逐帧精确校验。

修复后复用原 219 个已校验分段，在独立目录完成 CPU packet remux；没有重跑 SAM、GL 渲染或视频编码。两路各 13,116 帧的时间戳都与原视频按有理数精确相等，输出时间基均为 `1/90000`。经过任务、源视频、几何账本、旧分段和新媒体哈希验证后，恢复产物已发布到原任务。原始失败记录、检查点与分段保留，恢复 manifest 独立记录旧渲染版本和新 remux 修复版本。恢复过程单独计时，没有回填为原 A/B 的成功交付时间。

分段还有可测量的固定开销：A 的编码器建立和收尾合计约 0.277 秒；B 的 219 段累计约 46.553 秒。B 的逐段 PTS 校验累计 14.728 秒，A 的整片校验为 8.085 秒；拼接又需要独立验证。这些结果将后续优化重点指向分段编码器生命周期与重复验证成本，同时保留分段恢复和调度能力。本次只修复时间基错误，没有改变分段大小或减少校验。

结果一致性检查覆盖全部帧、native 记录、6,439 份主体网格以及完整评分证据：

- 全部 13,116 帧的源帧、检测、人物身份和相机运动字段一致；主体覆盖、帧绑定、PTS、网格 faces 和 focal 一致。
- 浮点坐标并非逐位相等。2D 关键点最大坐标标量差为 0.0001831055 像素，3D 关键点为 0.00000736117 模型单位，网格顶点为 0.00000751019 模型单位。模型记录使用 `model_units`，这里不换算为毫米。
- 原生关节角度最大差约 0.0003635022°；报告派生角速度的最大数值差为 0.00744°/s。两次旧版运行也出现了同数量级关键点浮点差异。
- 两轮均有 29 段挥拍，总分均为 88.55；`tennis-assessment` 响应内所有层级的 495 个 score 类字段完全一致。原始精确数值比较仍保留“不完全相等”的结果。

相关回归测试共 99 项通过。新增 CPU fixture 在旧实现上重现了“nominal codec fps 与精细容器时基不同”的拼接错误。浏览器验证通过：评分和五个维度显示正常，两路三维视频均为 960×448、437.144667 秒并可加载，页面、控制台与 HTTP 错误列表为空。切换视频时被浏览器取消的请求保留在测试回执中。
