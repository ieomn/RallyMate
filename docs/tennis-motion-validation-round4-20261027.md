# 动作分段、切削、接发与时序实拍验证（2026-10-27，第四轮）

本轮修复的是候选窗口、阶段绑定、初始化选人及关节缺测的作用域。计分曲线、五维聚合权重、发球评分参数和技术 profile 的要求集合保持不变。动作识别新增的序列规则与评分标尺分别记录；没有用职业/普通标签优化分差。

## 修复内容

- 发球准备不能从最后一帧抛球臂上举开始截取。沿实际已观测到的抬臂过程寻找开始，保留准备时的球拍证据；抛球、举手本身仍不构成发球。
- 候选搜索会检查满足原有条件的较长窗口，不再因为最短窗口缺球拍检测就丢弃整次挥拍。借用早期球拍证据时，持续低手位、近刚性手臂的转身仍不能升级为完整挥拍。独立低切削和连续两拍有反例保护。
- 较慢的准备/恢复回摆保留为同一动作的上下文，避免重复计数；真实独立展开、恢复后重新准备、不同持拍手证据、断帧等情况不会直接合并。
- 主运动峰在已有的连续上下文内寻找，避免把恢复动作的穿越时刻当成挥拍峰；持续静止的重新准备会阻止跨拍取峰。缺少持拍侧独立证据、两腕又出现相互竞争的运动序列时，明确标记阶段歧义，不回退到旧逻辑强行评分。
- 当外扩选中的完整阶段窗与原候选没有内部重叠（仅端点相接也不算重叠），最终窗口必须自己满足原有挥拍几何，不能借后续准备动作的跨身位移。缺少独立前挥证据的窗口保留 partial，不重新挑一个更有利的峰来凑完整动作；与原候选重叠的真实阶段不因峰偏移数帧而触发此限制。
- 评分模块尊重经过同源、人物、epoch、PTS 和完整阶段结构核验的上游阶段，避免再次选峰把完整前挥截回准备时刻。该峰表示画面运动峰，不是真实触球。
- 单腕异常按关节隔离。非持拍腕异常只使依赖该腕的指标缺测；持拍腕已知异常仍拒绝整段，且窗口首尾不能逃过检查。已知异常点在平滑前排除，不能从窗口外污染正常边界点。躯干、来源和人物参考断裂仍隔离整段。原 1.5 躯干长度跳变门槛未降低。
- 初始化缓存有 1.2 秒、96 帧、192 MiB 三重上限。确认人物后，只向前核对同 track、同机位、连续框和唯一衣着像素匹配的缓存帧，再按原顺序对各帧真实推理；不会把后帧姿态贴到前帧。保留原 unknown 原因与确认帧，歧义前缀不补。
- 已复核选人侧文件用于评分时，候选也从同一时间线重建。已验证的接发别名替代同一底线动作而非重复计数；仅有“接发”文字标签不构成来球证据。

## 真实材料与测量边界

THETIS 的两条原始 RGB 文件按 p1、p32 的第一遍示范预先选定，均为 18 fps 真人空挥。密集画面能确认 p32 的正手切削；p1 无法独立确认，保留 unknown，没有因结果不理想换样。p32 自动挥拍从零恢复为一个完整候选，但自动类型仍未分类。手工类型核验后的 profile 仅 **1/5** 项可测：阶段连续性。准备肩线短缩且没有独立目标方向，不能声称切削的前下轨迹已验证通过。

[THETIS 原始示范](https://github.com/THETIS-dataset/dataset/blob/main/VIDEO_RGB/forehand_slice/p32_fslice_s1.avi) 的媒体仅留本机；正式许可未在仓库明确，不随本提交再分发。

[Dimitrov/Tiafoe 实拍来源](https://commons.wikimedia.org/wiki/File:2024_US_Open._Grigor_Dimitrov_vs._Frances_Tiafoe.webm) 包含对手发球、近场来球和正手接发。重新生成正确目标的 native 姿态；人工独立完整窗口中，接发 profile **4/8** 项可测：准备配合、中心前移代理、向前挥出和连续性。对手/来球的逐帧人工证据带来源哈希；这不是自动接发判型成功，不加入自动命中率或自动总分。髋肩同峰，时序仍缺测。

ICS01 的完整自动阶段保持约 417–1285 ms，主运动峰约 1001 ms；人工只核验正手类型和持拍侧。独立时序测得肩峰约 834.167 ms、髋峰与腕峰约 984.317 ms。原公式得到 value 0.4、60 分，属于非理想顺序的画面代理，不能证明真实受力或理想动力链。缺测门槛、峰宽与分数曲线未为得到此结果而放宽。

原普通 B 完整发球的独立人工窗口仍只有 3/7 项可测，上下臂时序因投影短缩缺测。Davis 新推理补回 500–701 ms 的真实准备帧并恢复一个发球候选，但快速摇镜后的身份/姿态支持及随挥收束不足，仍保持 partial 和未评分；这是算法测量限制，不表示原画面换人或没有发球。

## 验证口径

25 份既有记录包含重复源、镜像和压缩版本，共 24 个文件 SHA；另有 4 份上轮 GPU 产物、4 份本轮 GPU 产物。不同组有重复视频，不能相加当独立样本数。旧版基线为 Git `b2b7f12` 的归档源码，同一组新旧版使用完全相同的 frames、timeline 和 native 文件。

本轮自动重识别对照不启用旧人工动作 context，所以分母与上一轮含人工无效片段排除的 72 段不同。独立手工窗口、人工类型绑定、自动分段和新 GPU 推理分别保存，不混为一个“成功率”。

源画面参考冻结为 9 源、12 动作，SHA `f6db76ba2ee118e0040bb3bab136544836ab1010913eb7438aad717a6bee5b04`。白衣末拍的稀疏帧标注偏晚，在密集复查后以独立勘误保存，原文件不改。Federer 早段原被误读为发球，本轮确认是接球准备和垫步，也保留更正记录。人工判断不是教练金标准或盲测。

窗口比较分别报告动作定位、阶段观测覆盖与峰时间误差；候选覆盖一个视觉锚点不等于阶段正确，更不等于触球准确。评分数量增加本身不作为准确率提高的证据。

## 最终回归结果

最终版本为候选识别 `v2.3.1`、阶段分析 `v2.7.1`、评分 `v1.3.0`、动作模式 `v1.1.0`，最终输出目录为 `release-v3-*`。三组旧版/新版对照的原视频、frames、timeline、native 哈希完全一致，运行期间源码和输入均未变化。

- 25 份既有记录：候选总数 133 → 133，可评分窗 79 → 81，有评分的记录均为 19 份。
- 4 份上轮 GPU 记录：候选 16 → 13，可评分窗 11 → 10，有评分的记录均为 3 份。
- 4 份本轮 GPU 记录：在相同新姿态上比较旧版/新版，候选 6 → 8，可评分窗均为 4，有评分的记录 2 → 3 份。不能将这个对照解释成新旧 GPU 模型准确率对照。

本轮另对 4 条原视频实际重新运行 GPU 推理，共产生 1,629 条 native 姿态记录，其中目标人物 1,457 条，其余为 Davis 同帧的其他人物。四次运行合计约 396.5 秒。捕获阶段的识别版本与最终 CPU 回放版本分开留档；没有为 CPU 修复重写姿态。

逐帧复查发现中间版本曾把 Rola 的准备动作重复计分，最终已合并为 12.880–14.348 秒的单次主动作。白衣低清片段主峰从恢复时的 6.467 秒恢复为 5.800 秒；22 秒片段两腕阶段归属不明，改为 partial。原白衣片段 5.8 秒和普通 B 34.5 秒也存在持拍侧支持冲突，保留未评分，不能宣称这些真实动作已恢复计分。

最后一次密集源帧审计还发现室外侧拍末尾的 27.750–28.375 秒是慢走举拍，不能算完整击球。原素材长约 480 秒，真正前挥在 30.333–30.500 秒、随后随挥约 30.667–31.000 秒，超出该份 native 的前 30 秒范围。保留 v2 失败审计和后续修复证据，不把“当前测量没有完整动作”写成“原视频没有动作”。

同一保护也使 Dimitrov 新推理中 13.633–14.200 秒的真实双手底线动作失去评分：其阶段窗完全位于后续候选之前，画面中的横向幅度约 0.024 躯干长度，当前跨身几何不足以独立核验。原片确实有挥拍，这是视角与规则导致的覆盖损失，不是剔除假动作；没有为保留职业视频分数而放宽条件。独立完整接发人工窗仍为前述 4/8，不受这一自动阶段变化影响。

仍保留的限制包括：快速连续挥拍可能受原有最小峰间隔影响；镜像、短缩、摇镜与持拍侧冲突会限制测量；新增切削材料并未补齐独立方向与全部发力指标。上述缺测不按零分处理，也不作为动作差的证据。

最终 30 个后端测试模块共 **377 项通过**；前端 **918 项通过、1 项跳过、0 项失败**，构建、lint、类型检查通过。测试包含源绑定、主体隔离、准备/恢复反例、连续两拍、阶段权威校验、持拍腕首尾异常、窗外异常隔离和不可观测时序，相关子集不重复累加。完整自动报告另经过前端严格解析检查。

本机服务已更新，并核验 9 份带既有人工审阅的实际接口报告。为避免检测版本改变 episode ID 后丢失审阅，8 份报告中 15 条原有审阅在严格核验旧 ID、源文件、track、窗口、epoch 与时间线完全一致后追加新绑定，原条目与备份保留；变窗的条目不迁移，ICS 的新类型绑定单独留证。其中 6 条既有人审持拍手与模型阶段持拍手冲突，继续保留人审事实并明确拒绝评分，没有删除人审后退回通用指标打分。这些是测量覆盖限制，不表示动作本身不合格，也不混入前述无人工 context 的自动回归统计。

## 复现

证据目录：`docs/evidence/tennis-motion-validation-round4-20261027/`。原视频、完整 native 和探索性输出留在本机 `.codex_tmp/tennis-score-round4-20261027/`，旧冻结证据不覆盖。

- `scripts/validate_tennis_identity_pipeline.py`：对原视频重新执行检测、初始化缓存、身份锁、SAM 和候选识别；输出帧/PTS/身份绑定与代码哈希，不生成网格预览。
- `scripts/replay_tennis_segmentation_validation.py`：以 `--manifest`、`--source-code-root`、`--output` 比较旧版/新版；拒绝覆盖或输入/代码在运行期间变化。
- `scripts/compare_tennis_action_replays.py`：以 `--reference`、`--evaluation`、`--output` 对固定源参考进行一对一核对，不修改任何预测。
- `scripts/validate_tennis_manual_patterns.py`：独立人工窗验证；真实接发需要同源的对手与来球帧证据，缺证据则保持 generic。其结果不冒充自动分段。

本轮真实推理时的代码均冻结；之后的候选搜索与关节作用域修复在同一份不可变 native 上 CPU 重放。推理版本与最终评分版本在证据中分别记录。
