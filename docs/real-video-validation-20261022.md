## 标注和计量语义

动作标注来自代理对原始解码画面的逐帧视觉审查，前挥锚点不确定性约 ±150 ms；不是教练认证标签、真实触球标签或 A–E 真值。视频来自教学机构也不能自动将动作评为 A。

匹配采用最大数量、最小代价的一对一动作窗匹配，要求候选与参考前挥窗重叠至少达到参考窗时长的 20%。同一动作的重复候选计入误候选，未匹配动作计入漏检。等数量匹配优先重叠较多、锚点较近的候选，避免宽泛准备窗占用正确前挥。阶段峰值误差另计；未知技术类型和腕侧不一致不计为正确分类。前挥窗口召回率不等于触球检测召回率。

本地两例没有穷尽标注，不能报告它们的召回率和误检率；只报告本轮实际输出数和待审窗。相机和关节覆盖由原观测校验，模型有坐标不等于已验证真实可见。

## 本轮实际漏检及副路收益

1. **正手**：主路 6 个候选匹配四次前挥中的 3 次，漏 1 次、误候选 3 个。副路增加 2 个复核窗后，4 次前挥全部可定位，误候选总数变为 4。主路精确率 3/6，主路加复核队列精确率 4/8；没有用更多候选掩盖误报。
2. **双反**：主路 2 个候选匹配 2/4 次前挥。副路新增 2 个复核窗后定位 4/4 次，当前标注窗内没有额外误候选。
3. **保留单反**：主路 4/4，副路 0 个新增窗；已有一次腕侧与右手持拍视觉证据不一致，仍未修好。全部技术类型仍需区分未知状态，不能说已正确分类四次单反。
4. **本地背视视频**：重新回放输出主路 30 个、副路 4 个复核候选。**本地手持视频**：主路 5 个、副路 3 个复核候选。这些数量没有标注精确率保证，不能宣称新增窗都是漏检修复。

三个公共视频合计，主路前挥窗召回 9/12；加入复核队列后 12/12。新增四个复核窗中三个对应原漏检，一个为回拍动作误候选。这是三个小片段、人工估计动作窗上的结果，不是自动原卡评分成功率。

可复查的具体失败：

- 正手约 **10.820 秒**：原主路局部几何已满足要求，10.687–10.954 秒窗口水平位移约 1.049 个躯干单位、垂直变化约 0.947，球拍关联 3 帧。它被 9.687 秒左手准备候选和主路 1200 ms 峰值去重压掉。副路恢复 10.687–11.020 秒复核窗，主路去重逻辑本轮未冒险放宽。
- 双反 **9.554 秒、13.220 秒**：实际前挥以斜向/竖向运动为主，候选窗口两端水平变化约 .405/.563 个躯干单位，低于主路 .9 水平阈值；欧氏位移约 1.342/1.267。新副路不要求水平跨体，因此能提出复核窗。
- 正手 **7.820 秒**：回拍回收运动也满足副路的位移和球拍条件，是本轮明确保留的误复核。不能计击球，不能给分。
- 双反第一动作：主路候选可定位，但阶段分析峰漂到 **2.554 秒**，参考前挥锚点约 1.850 秒，偏差约 704 ms；其阶段窗口未覆盖该参考前挥。副路不修复已有候选的阶段边界，这仍是待修问题。
- 背视本地视频 1.100–2.100 秒 FS01 事件中，近端球员是站立/调整脚跟，现有垫步起落锚并不可靠；髋部局部下降不能单独证明垫步。相关连续窗验证见 `docs/temporal-card-evidence-v1.md`，不能把其待复核候选计作已确认垫步。

## 副路计算和边界

`stroke_review_fallback.py` 已接入正式 `detect_stroke_candidates`，输出独立的 `review_candidates`，保留原 `candidate_count` 与正式评分路径。

- 保持同球员、选择阶段、相机参考、归一化和源时间连续性，不插值、不跨身份重关联。
- 至少连续 5 个观测样本，窗口 300–1000 ms；局部腕速峰不低于 2 个躯干单位/秒，欧氏净位移不低于 .8 个躯干单位。
- 净位移/轨迹长度至少 .55，近腕球拍关联至少 2 帧，起止速度均低于峰值 .8；排除过顶动作。
- 距主路窗口 800 ms 内的峰不另建复核；复核峰 900 ms 内按运动峰强度合并，防止准备和回拍大量重复。该策略可能合并快速衔接动作，尚未用高速多球标注集验证。
- `off-axis-swing-review-v1.0.1` 的主路去重必须将主候选起点、峰值和终点的原始帧号与时间回查到本批观测，并确认选择阶段、相机参考、归一化和源视频一致。仅球员编号相同、时间相近不再足以压掉复核窗。缺失/冲突源锚不用于去重。五视频重放的候选数和匹配结果未因该边界修复改变。
- 这些是开发集上明确冻结的工程候选阈值，不是 Word 原文阈值，也不是专家标定。副路不能推断持拍手、真实触球、技术质量和原卡等级；输出 `manual_review_required`、`automatic_scoring_allowed=false`。

## 真实评分窗执行

用三个视频的 12 个准备阶段人工锚窗调用当前 `card_kinematics` 和 `evaluate_card_window`，覆盖 60 次卡片执行：**27 次视觉代理可评分、16 次人工复核、17 次不可评价、0 次原卡自动等级**。涉及 15 张准备期卡，其中 9 张至少有一次代理分。

- 正手 20 次：12 代理、8 复核。
- 保留单反 20 次：13 代理、4 复核、3 不可评。
- 双反 20 次：2 代理、4 复核、14 不可评。左右肩髋等关节联合覆盖不足以及不完整时间窗阻止了评分；不可评没有变为 E/0。

推理产物原先只保存 rounded decoder timestamp。当前重放又实际解码原下载视频，用 FFmpeg `showinfo` 取每帧真实 PTS 与 `1/90000` 时间基，按帧号与姿态观测对齐，校验时间差不超过 .51 ms；没有用 FPS 合成 PTS。读取前核对原视频和 `frames.jsonl` 与 run provenance 中的 SHA256。完整解码时间线保留缺姿态帧作为分母；数字关节集合按卡联合检查 70% 几何覆盖。人工锚阶段只适用于这些已审查窗口，不代表把三阶段自动挥拍扩成十阶段原卡边界。

CI 小型真实回归检查：GS01-M03-01 的实际代理条件值与得分；GS02-M03-02 因真实原观测关节覆盖不足拒绝评分。测试对数值、覆盖分母和 null 原卡等级作断言，不只断言返回列表长度。

## 复现

已存在的本地文件直接执行：

```powershell
python scripts/replay_card_video_validation.py
```

在有 CPU YOLO26n 权重的环境重新下载、推理全部公共示范：

```powershell
python scripts/replay_card_video_validation.py --download-public --infer-public
$env:PYTHONPATH='src'
python -m unittest discover -s tests -p test_card_video_validation.py
python -m unittest discover -s tests -p test_card_real_window.py
```

未提供的私人原视频明确输出 `not_run`，不会默默算入成功。公共下载只接受目录里的 HTTPS MIT Archive.org 链接，下载前后核对 SHA256，最大读取 20 MB。测试夹具可在不下载原视频、无 GPU/模型的 CI 中重算实际已存数值观测；该 CI 不是新的端到端视觉推理。

尚需真实验证：切削、左手、侧视极端缩短、多人多球、严重遮挡、高速快速衔接和片段截断。现有副路收益不足以宣称这些场景已解决，97 张缺失阶段的工程修订也不能仅凭这些 12 个窗口视为验证完成。
