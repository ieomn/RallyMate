# RallyMate 账户系统交付与验收

日期：2026 年 11 月 17 日  
范围：注册审批、登录鉴权、个人历史、管理员后台、PostgreSQL 迁移、Linux 部署与监控

本次实现沿用 React / Vinext、FastAPI 和独立推理 Worker，在入口、账户模块和存储适配层增加身份、权限与数据归属。生产主库使用 PostgreSQL，本地保留 SQLite。实施依据为已经批准的[技术栈与修改清单](RallyMate技术栈确认与修改清单_20261117.md)，按存储与迁移、后端权限、前端页面、部署监控、联合验收五个阶段完成。

本地运行、Linux 初始化、历史迁移、备份恢复和上线检查的完整命令见[部署手册](../deploy/README.md)。监控面板、告警接收器与 SSH 隧道见[监控手册](../deploy/monitoring/README.md)。本次使用独立数据库、测试目录和隔离 Compose 项目验收，原 `service_data` 没有执行迁移或清理。

## 1. 已交付的使用流程

1. 用户在 `/register` 提交邮箱、显示名称、密码和申请理由；新账户为 `USER / PENDING`。
2. 用户可以登录查看审核状态。待审核、拒绝或封禁账户不能上传视频、创建分析或读取业务结果。
3. 管理员在 `/admin` 按状态筛选账户，执行通过、拒绝、封禁、删除和密码重置，并查看注册人数、待审核人数及用户调用统计。
4. 审核通过后进入工作台；历史列表从服务端按当前用户查询，视频与报告继续使用原有回放界面。
5. 管理员重置密码时，后端生成 35 字符随机临时密码并撤销目标用户所有旧会话。密码仅在当前弹窗显示并支持复制，关闭或离开后清除；后端只保存 Argon2id 哈希。用户用临时密码登录后须先设置新密码，随后重新登录。整个流程不使用邮件服务。
6. 退出登录撤销当前会话；封禁、删除、重置密码和修改密码撤销相应旧会话。删除用户采用逻辑删除，保留任务归属、历史调用统计和管理审计。

登录标识为唯一邮箱，显示名称可重复。密码要求 12–128 字符并包含字母和数字；后台临时密码使用密码学安全随机源生成。最后一个有效管理员受到保护，避免误操作使后台失去管理入口。

## 2. 后端权限与数据隔离

JWT 默认有效期 7 天，包含签发者、受众、用户 ID 和会话 ID，并与数据库中的可撤销会话绑定。浏览器使用 HttpOnly、SameSite=Lax Cookie，生产启用 Secure；浏览器 Cookie 会话的写操作同时检查 Origin 和 CSRF token。API 也接受当前用户的 Bearer JWT。

每次受保护请求读取当前账户状态。共享 `RALLYMATE_API_KEY` 保留运维用途，不能代替普通用户登录。上传入口先执行鉴权，再读取大请求体。输入校验、参数化数据库访问、注册登录限流和统一异常响应由新增边界实现。

| 场景 | 服务端结果 |
|---|---|
| 未登录访问上传、推理、历史、结果或删除接口 | `401` |
| 登录但未通过审核，或必须修改临时密码 | `403`，返回对应原因 |
| 普通用户请求管理员接口 | `403` |
| 访问其他用户的任务、上传会话、原视频、报告或回放资源 | `404`，不透露对象是否存在 |
| 管理员读取其他用户的视频或报告 | 同样受个人归属限制；管理员角色不授予视频读取特权 |
| 删除仍在排队或执行中的任务 | `409`；先取消并等待任务进入终态 |
| 终态任务逻辑删除后再次访问 | 历史列表移除，资源接口返回 `404` |
| 历史任务 `user_id IS NULL` | 保留原数据；任何个人账户均不能通过业务 API 读取 |

归属检查覆盖列表、详情、状态、取消、删除、分片上传全过程、原视频 Range 请求、报告分页、回放、技术复核、下载和前端 advice API。浏览器五类历史、活动任务和续传缓存按用户 ID 隔离；账户切换会取消旧请求，防止延迟响应写入新账户界面。

主要新增接口如下，既有 `/v1` 推理与资源接口保留原路径和业务行为：

| 方法与路径 | 用途 |
|---|---|
| `POST /api/auth/register` | 注册申请 |
| `POST /api/auth/login` | 登录并设置会话 Cookie |
| `POST /api/auth/logout` | 撤销当前会话 |
| `GET /api/auth/me` | 当前用户、会话到期时间和 CSRF token |
| `POST /api/auth/change-password` | 修改密码并撤销旧会话 |
| `GET /api/records` | 当前用户的分页历史 |
| `DELETE /v1/jobs/{job_id}` | 逻辑删除自己的终态记录 |
| `GET /api/admin/users` | 管理员分页列表和状态筛选 |
| `GET /api/admin/stats` | 用户及调用统计 |
| `PATCH /api/admin/users/{user_id}/status` | 通过、拒绝或封禁 |
| `DELETE /api/admin/users/{user_id}` | 删除账户并撤销会话 |
| `POST /api/admin/users/{user_id}/reset-password` | 生成仅在响应中返回一次的临时密码 |

统计分别保留提交任务数和执行尝试数。自动重试产生新的执行尝试；排队后取消不计为执行；失败尝试计数；逻辑删除不清空累计统计。

## 3. 数据库、迁移与历史兼容

新增 SQLAlchemy Core 模型和 Alembic 版本 `20261117_01_accounts`，包含用户、会话、上传归属、管理审计和限流表。`jobs` 增加可空、带外键和索引的 `user_id`，以及逻辑删除字段。现有 SQLite 队列继续通过兼容接口运行；PostgreSQL 适配保持原子领取、容量限制、取消、执行尝试归属和恢复语义。

生产部署先显式执行迁移，再启动 API 与 Worker；普通服务启动检查版本，不在多个进程中竞争执行生产 DDL。首次 API 启动读取 `ADMIN_EMAIL` 与 `ADMIN_PASSWORD`，仅在没有管理员时创建 `ADMIN / APPROVED` 账户，重复启动不会覆盖已有密码。

迁移工具支持只读 SQLite 快照、Windows 到 Linux 路径映射、预检查、幂等导入和导入后校验。实际历史演练使用 626,229,248 字节的原库快照：

| 核查内容 | 结果 |
|---|---|
| 历史任务 | 154 条：145 成功、6 失败、3 取消 |
| 首次导入与重复导入 | 154 条保留；重复导入不重复创建 |
| 任务 ID、状态、完整摘要 | 校验摘要一致 |
| 原视频与请求文件引用 | 各 154 个均存在 |
| 输出目录 | 152 个存在；2 个取消任务原本没有输出目录，成功任务输出均存在 |
| 原数据库 | 快照前后主文件 SHA256 一致；未对原库写入账户字段 |
| 历史归属 | 全部保留空归属，不自动分配给管理员 |

这次演练验证数据库导入和路径转换，没有复制实际媒体到服务器。部署时按手册复制媒体和报告，再核对目标文件。运维 CLI 可将指定无归属终态记录分配给指定用户，并写入审计；不会批量开放所有旧视频。

记录物理回收通过独立维护命令执行，要求任务终止、记录已删除、文件位于受控数据目录内。其他记录仍引用的目标会被保留并报告，符合条件的独占文件继续回收。Linux 使用目录文件描述符相对删除，Windows 使用已打开对象的删除句柄，防止目录替换、符号链接或 Junction 将回收操作导向目录外。

## 4. Linux 部署与运维

| 组件 | 交付配置 |
|---|---|
| PostgreSQL | PostgreSQL 17，独立持久卷；不公开数据库端口 |
| API | Python 3.12 CPU 镜像，独立于 GPU Worker；非 root 用户运行 |
| 前端 | Node 24.22.3 生产镜像；React / React DOM / RSC 同步固定 19.2.9 |
| 同源入口 | Nginx HTTPS，`client_max_body_size 2G`；上传和代理超时 3600 秒，关闭上传请求缓冲 |
| Adminer | `127.0.0.1:8080:8080`；通过 SSH 隧道访问 |
| Worker | 默认单副本；显式选择物理 GPU，容器内使用逻辑卡 0；保留既有 GPU 锁与设备配置 |
| Prometheus / Grafana | 指标抓取、告警规则及自动预置的 16 面板看板 |
| node-exporter / DCGM | CPU、内存、负载，以及按 GPU UUID 区分的利用率和显存 |
| Sentry | Python API / Worker 与前端浏览器 / Node 入口均可按环境变量启用 |
| Uptime Kuma | 可选 `uptime` profile，管理端口仅绑定本机回环 |

Nginx 是公网入口，`/metrics` 与内部维护路径不对外提供。API 指标另用专用 token；Grafana 使用独立密码文件。Prometheus、Grafana、Alertmanager、Adminer 和 Kuma 的宿主管理端口均限定回环地址。密钥生成工具拒绝覆盖已有配置，`.env`、密钥文件和本地测试数据均被排除在 Git 与镜像构建上下文之外。

告警覆盖服务不可用、数据库异常、CPU/RAM、显存、5xx 和延迟；默认接收器只在本地展示告警。邮件、Webhook 与飞书接收器示例由运维填写实际接收端后启用。密码重置不依赖这些通知组件。

Sentry 保留用户 UUID、任务标识和安全代码栈；过滤凭据、请求正文、原始异常文本、文件内容和敏感上下文。没有 DSN 时不初始化外部传输。自动验收使用本地假传输，没有上传真实视频、用户密码或报错到外部 Sentry 项目。

SAM3D 继续使用现有匹配模型的运行镜像；仓库 CUDA Dockerfile 对应 RTMPose 路线。模型与运行时主目录只读，数据、缓存、日志和 GPU 状态目录可写。本轮没有改变 GPU 调度，也没有把 API 进程扩展成多副本推理器。

### 5.1 扩大回归中的现有失败

更广的非 API 回归实际结果为 **3,848 通过、190 失败、76 错误、24 跳过**，另有 8,686 个子测试通过。失败报告中的一项是本次部署文档遗漏评分注册表变量，已补齐并单独复测通过。其余 265 条失败或错误报告按根因分布如下；同一初始化异常可能产生多条错误报告：

| 根因类别 | 报告数 |
|---|---:|
| 已有注册表、truth 或 replay 绑定身份与测试数据不一致 | 148 |
| 已有评分与冻结快照预期不一致 | 59 |
| FootCrossing producer 身份约束 | 47 |
| Windows 测试夹具 SQLite 连接未关闭导致文件占用 | 8 |
| Worker 旧 Mock 与现有执行状态读取接口不一致 | 1 |
| 旧 smoke 测试期待 v2，当前生命周期为 v3 | 1 |
| 既有报告内存增长断言超出阈值 | 1 |

涉及这些结果的 50 个测试文件没有修改，相关受保护核心源码与实施前一致；代表性失败已独立复现。本次没有放宽这些断言、添加预期失败标记或修改评分与推理实现。因此，账户与部署专项通过不等于整仓业务回归全部通过；正式发布应同时处理既有业务回归和下述目标服务器验收。

### 5.2 目标服务器验收范围

当前真实浏览器验收完成上传、入队和取消，没有启动 GPU 推理。本机未执行目标多卡服务器上的 SAM3D/CUDA 推理、GPU/DCGM 实测及外部通知验收。部署手册提供上线检查步骤：在目标机器以所选单卡完成视频推理与回放、验证 GPU 指标，并在配置接收端后验证通知。

Nginx 的 2G 限制已通过实际配置校验；本次浏览器上传样本约 3.9 MB，没有传输完整 2 GB 文件。CPU/RAM 与 GPU 指标也不代表多用户压力测试或 GPU 容量结论。

依赖安全检查修复了 React/RSC 的 Critical 告警，npm audit 剩余 17 High、15 Moderate、1 Low，主要位于开发与构建依赖链。实际输入路径、生产命令与后续依赖更新边界见[前端依赖安全验收](RallyMate前端依赖安全验收_20261117.md)。
