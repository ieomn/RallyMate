# 摘要与动作证据分段交付（2026-11-07）

新增链路直接读取完成任务的聚合值和保留产物，不构建原先的整份 `demo-result`，不重新执行姿态推理，也不提高旧完整报告的证明数量、展开字节或节点上限。旧接口保留兼容性。`summary: complete` 仅指新的轻量摘要合同完整，不代表旧完整报告已生成成功。

| 接口 | 内容与界限 |
| --- | --- |
| `GET /v1/jobs/{id}/status` | 直接查询小型状态/进度投影，不解析或传输多兆字节 `summary_json`，不重新识别动作 |
| `GET /v1/jobs/{id}/report-summary` | 持久化视频参数、处理统计、测量/评分状态、动作候选计数、独立媒体入口；256 KiB 上限 |
| `GET /v1/jobs/{id}/report-actions?offset=0&limit=20` | 动作元数据及证据状态，默认20条、最多50条；256 KiB 上限 |
| `GET /v1/jobs/{id}/report-actions/{event_id}?offset=0&limit=4` | 一条完整事件及该事件的完整指标记录分页，默认4条、最多8条；8 MiB 上限；沿用严格 `model-proof-pool-v1` |

动作页/详情页返回明确 `partial` / `complete`、总条数及 `next_offset`。单条证明不会为适应页面而截断。超限返回413，可以减小 `limit`；如果一条仍超限则保留失败状态和原始产物。校验未通过的动作候选仍在列表中标为 `failed`，不会冒充“没有动作”。

每个响应绑定 `job_id`、原推理任务、视频及帧文件 SHA。`source.evidence_revision` 由事件文件、指标文件、证据池摘要及协议版本计算，用于拒绝同视频重新生成证据后的跨页混合。交付前后还对数据库摘要原文取摘要，即使同状态、同 `updated_at` 的改写也拒绝交付。

事件/指标产物与证据池按持久化摘要中的 SHA 校验；流式建立有界字节位置索引，不缓存整个展开报告。读取目标动作时恢复完整记录，检查事件、逻辑主体和原生主体、视频、PTS、连续源帧、选择 epoch、相机 epoch、几何 mask 及未知嵌套证明。随后流式校验完整 `frames.jsonl` 摘要，只解码当前动作需要的帧，与该帧原生 `pose.source_binding` 独立逐字段比较。因此748 MB帧文件无需整文件JSON加载，也无需放宽512 MiB旧视图读取上限。

逻辑 `person_track_id` 与原生 `source_track_id` 是不同身份层次。真实任务的逻辑主运动员可以一直为1，而后期原生track为986；不能直接要求两者相等。前端与后端都分别保留并验证这两个绑定。

索引缓存最多4项、保守记账总预算16 MiB；只缓存元数据和位置。每次命中仍校验内容摘要，防止同大小并恢复mtime的文件替换。独立读取槽最多2个，忙时429；每次读取有60秒及既有进程内存预算，支持任务取消与客户端断开。摘要仅给出 `/mesh-preview` 入口，三维生成与进度仍由既有独立后台协调器负责。
