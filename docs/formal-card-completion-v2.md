# 内部条件完成率分数 v2

`automatic-formal-card-scoring-v2.0.0` 只修正内部完成率与分数的算术关系：

`score = 100 × 已通过条件数 / 必需条件数`。

条件值全部可计算时，0/N 为 0；没有条件或缺少任一必要条件值仍为空分。原 A–E 分类边界、条件定义、阈值、来源及原始运动测量不变。A–E 仍是工程分组，不能用来反推出 v2 分数。旧 `GRADE_POINTS` 留给目录内部代理及历史 v1。此修正不是连续关节运动质量标定，也没有建立专家百分制或准确率。

Python 先由原计算器产生内部代理结果，再按本策略转换；已完成的 v2 结果再次处理时按同一完成率公式校验，保持幂等。FS05 的两个独立消费者在重新计算新条件后丢弃不可用模板的策略标签，再执行当前转换。历史显式 v1 结果只按原分档公式验证，不自动改成 v2。旧未知策略、错误分数、缺值或后续来源拒绝不能进入正式总分。

总分仍先平均同卡的多次动作，再等权平均有分的卡，缺测留在覆盖率分母而不补零。汇总器不会混合 v1 和 v2 实例为一个正式总分。浏览器由生成的策略合同识别两版本，独立重算条件和对应版本的分数；只改历史报告的版本标签、保留旧 60 分，会因与 v2 完成率不符被拒绝。

已有 native e420 的固定 112–136 原帧录制观测用于 fresh 生产函数回归：FS05-M02 1/2 为 50，M03/M04 2/3 为 66.666…，均仍为 C 类。旧真实 HTTP fixture 的三张 60 分与 v1 标签原样保留。它们的几何、条件值和原窗不随分数修正而改变。

专项覆盖 0–4 个条件的全部完成数、重复处理、缺测、旧版保留、篡改版本、等权汇总、真实录制观测重算，以及 Python/TypeScript 算术一致性。完整物理源重放另存；可通过 `FORMAL_V2_REPORT` 向浏览器测试提供实际重放的统一报告，验证计数、总分和再次读取一致。没有为测试制造新的真实动作窗口。

相同原始数据、事件和来源窗口的完整重放保留了全部 265 个实例的观测、条件和可用状态：run `0a3df3a3-2629-4dd5-80a1-54e4b11f7341` 的 200 实例仍为 115 有分、85 缺测，总分 55.0291 → 52.1823；run `b10f614f-b1c1-4207-b9d4-50082eb43164` 的 65 实例仍为 40 有分、25 缺测，总分 52.8938 → 48.6410。差异仅是版本标签与分数公式，并不表示动作识别准确率下降或提升。两份新版实际报告均通过浏览器独立重算和往返读取检查；历史报告没有被覆盖。
