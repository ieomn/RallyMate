# 四张迈步卡的二维运动证据

前端仅为 `FS02-M04`、`FS07-M02`、`FS08-M02`、`FS08-M03` 接入 `step-motion-evidence-v1.0.2`。人工窗口与观察到的移动脚不能直接授权评分；原卡等级始终为空。FS08 使用“跨步”，FS07 只称“观察到的移动脚”，不由脚的速度推定前脚或目标方向。既有 FS03/FS04 仍由其独立脚序验证器处理。

`fs-step-motion-display-contract.ts` 从后端注册四卡与工程政策生成，原目录条件不变。读取器从 `source_geometry_series` 的六关节归一化坐标、原置信度和观察语义重算共同有效帧；以完整原帧库存为分母。模型缺置信度例外还要求每帧 `source_binding` 与原 PTS、视频、人物及两个分段一致，单独自称模型语义不能授权。所有原帧、PTS、时基、视频、选人和相机分段必须连续一致。它不信任保存的 `valid_source_frames`、`complete_visual_motion_cycle`、`step_cycle_bound` 或评分字段。

这里的 `normalized_points` 是 `_sample` 对**相机补偿参考平面**逐帧归一化后的坐标，并非未经补偿的原图坐标。读取器从 `reference_series` 六关节重新计算肩中心与 `max(肩髋中心距离, 肩宽×0.75)` 尺度，再逐关节核对归一化值；仅接受 `full_torso`。冻结归一化序列、交换左右踝或把参考像素冒充归一化坐标都会拒绝评分。

二维相邻速度来自固定相机参考点，尺度是全窗躯干长度中位数。观察到的移动脚需要连续低速—移动—低速三段，每段至少 80 毫秒与 3 帧；相邻段共享边界帧。固定首尾窗口为 `max(3, ceil(n×20%))`，不得缩短到低速段。首尾中位数距离必须大于两段低速点云半径之和；另一脚也具有完整运动片段，或另一脚净位移、路径长度任一超过声明脚时，都拒绝评分。这个速度分段政策不能区分连续高速弧线中的多个技术动作，也不证明足底触地。

三个位移条件仍采用两踝净位移较大值；稳定性条件仍采用完整两踝路径较小值/较大值。FS08-M03 的躯干角范围独立从上述已核对的归一化坐标重算，保留后端现有公式。数值与条件数学匹配后，还要经过原 `validFsWindow` 的文档、原始质量、身份诊断及全窗质量覆盖检查。带 `automatic-formal-card-scoring-v1.0.0` 的新报告中，七类候选质量提示只作为来源备注；完整来源与数值通过校验后正式评分。已确认身份切换、原帧/时钟/几何缺失以及完整质量覆盖缺失仍不可评分。无新政策标记的历史代理报告保留旧规则。非法运动记录只保留诊断与备份，条件表不把其数值显示为有效测量。

面板保留人工窗口不确定性、声明脚、两个脚的全部片段、实际 PTS、双踝二维序列和完整六关节证据。备份保留所有原始 `source_window_evidence`，读取时重新生成 `step_motion_validation`；导出只使用该次复算的运动说明。浏览器核对报告内部的绑定和算术，不重新解码视频，也不独立确认真实身份或技术。

新应用评分政策允许来源绑定完整的单目模型及混合测量生成正式分数；`measurement_provenance` 原样保留。模型语义本身不能替代逐帧来源绑定，也不能救回缺失或不合法几何。模型估计仍不证明关节真实可见或原卡技术等级。

`scripts/build_fs_step_motion_display_fixtures.py` 从正式原记录适配器计算 **22 个合成合同样例**，包括四卡完整片段、完整低位移 E、79/80 毫秒边界、两次运动、短段、端点窗口跨越运动、回原位、错脚与竞争脚、原质量警告、关节缺测、相机旋转补偿及经过正式模型来源解析的缺置信度模型例子。它们使用合成轨迹，不是原视频动作阳性；真实完整 FS4 正例仍为 **0**。测试外壳不代表生产 HTTP 验证。

运行生成器重建合同与样例；`build_fs_step_motion_display_contract.py --check` 核对注册政策。历史回归为 `fs-step-motion-evidence.test.mjs` 与 `fs-step-motion-export.test.mjs`；新政策回归为 `formal-card-execution.test.mjs`。生成器另写 `fs-step-motion-formal-synthetic-contract.json`，不覆盖历史样例。旧四卡缺少运动观察或 v1.0.2 几何证据时保持无分，手工窗口不会被补成完整运动。


模型 detector epoch 与下游主球员选择 epoch 分开保存。只有显式 `detector_track_epoch_primary_selection_applied_downstream` 契约才接受两个命名空间不同；原模型 binding、几何序列和逐帧来源中的模型 epoch 必须一致且连续，主选择 epoch 仍匹配完整父窗。缺 marker 的历史数据沿用原相等契约。
