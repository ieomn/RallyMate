# 关节计算与训练评分修正

评分卡是内部规则和计算记录。用户报告只显示选定的一份训练总分、动作观察及建议；完整规则、来源与逐次测量保留在机器备份中。内部规则的数量不能表示实际执行数量或识别准确率。

## 关节数据路径

运动分析使用原姿态识别结果中选定球员的关节坐标、来源帧与时间戳。腕部路径相对身体参考点并按躯干长度归一化，速度单位是躯干长度/秒。当前修正针对二维投影运动，没有将 SAM 三维模型估计冒充解剖真值，也没有根据期望成绩改动关节数据。

旧阶段入口与过程入口分别采用不同宽度的逐坐标中值滤波；这种滤波不与坐标旋转交换。现在两处共用 `vector_kinematics.py` 的时间加权向量拟合，再用相邻点差除以实际时间差计算区间速度。完整定义与不确定性见 [vector-kinematics-v1.md](vector-kinematics-v1.md)。动作分析版本升为 `stroke-motion-analysis-v2.5.1`，旧摘要需要从源观测重算。局部窗口缺帧导致连续运动不可测时，仅取消该候选的测量，保留其余动作；不跨缺口求速度，也不吞掉其他程序错误。

## 正式评分

`automatic-formal-card-scoring-v2.0.0` 保留现有观测、判定条件和 A—E 分类，将每次测量的数值成绩改为：

```
单次成绩 = 100 × 已满足条件数 / 具备完整测量的规定条件总数
单项成绩 = 该项去重有效动作的单次成绩均值
训练总分 = 所有已评分项目的单项成绩均值
```

所有规定条件都有实际值后才能计分；缺失条件不会从分母移除以抬高成绩。全部条件未满足时是真实 0 分。没有可计算条件时为空，不补 0、20 或 50。冲突的重复动作不参与汇总。原 A—E 分类继续保留在内部，它不再把连续的完成比例强制映射成 20、40、60、80、100。

例如 0/2、1/2、2/2 的新成绩为 0、50、100，旧分档为 20、60、100；1/3 和 2/3 的新成绩为约 33.33 和 66.67，旧分档为 40 和 60。这修正了条件完成率与数值成绩之间的偏差，不是新的网球技术阈值标定。

旧 v1 报告按原版本验证并保留原分。新版成绩必须来自相应版本的计算，不把旧的已存总分重贴新版标签。前端仍从有效条件验证分数、对去重动作与项目重新求均值，不信任保存的总分。

## 过程分与用户总分

`relative-reference-v3.0.0` 去掉缺项填 50 和 `n/(n+3)` 收缩。同样质量的动作不会只因视频长短改变分数；真实零分与缺测严格区分。旧 v1 曲线诊断与旧 v2 中性先验结果独立留作历史，不进入当前过程成绩。

目前过程分只有独立目标方向一致性这一条有效规则；缺少独立目标时不会从腕速趋势拼出五维技术分。腕速上升、下降比例仍可作为测量记录，但不能因窗口正是按峰值选择，就将它解释为优秀挥拍。

`trainingScoreOf` 优先选择通过内部条件校验、且与外层视频任务一致的正式成绩；没有正式成绩时才使用有效过程成绩。两者不混合平均。过程图只绘制各项已有观测对应的分数，不把训练总分复制到五个维度。无评分依据的项留空。

## 验证范围

真实用户视频的原识别轨迹用于回归，原视频、帧、选人文件和历史报告均保持不变。固定动作窗口验证速度旋转/平移不变性和两入口一致性；从原观测完整重算另外检查阶段边界变化。正式评分的新旧比较必须固定相同窗口、条件、观测及阈值，单独衡量公式变化。

这些检查证明计算的一致性和版本行为，不代表完成了教练评分一致性验证。二维投影缩短、遮挡、持拍侧关联、触球定位及未标定的判定阈值仍会影响结果，不能以通过来源校验或单元测试代替技术准确率。
