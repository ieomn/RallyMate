## 带评分基线的语义

旧数字由可测片段比例、必需特征覆盖、特征置信度、跨片段重复性和评分证据覆盖合成，原权重分别为 30%、20%、15%、25%、10%。这些量描述证据与重复性，尚不是技术好坏的教练评分。

- 恢复时使用显式 `score_semantics=measurement_evidence_quality`，页面和报告标记为参考分。
- 缺失重复性保持空值，不补 50；仅在有测量时按可用成分重新归一化权重。空证据不生成分数。
- 正式技术分和等级继续为空，不能从证据分高推导“动作好”，也不能据此跨视频比较水平。
- 前端 API 适配、导入、页面、Markdown/HTML 报告和 JSON 备份必须一致。无明确语义的历史数字不自动当作可信参考分。
- 二维肩线/髋线变化仍是投影测量，不当作人体真实轴向转体角。旋转评分重构不能只把角度大映射成高分。

## 当前代码与需要优先处理的原因

推理链路：原视频解码 → 人/球/球拍检测 → 跟踪 → 人框 RTMPose → 主球员 → 步伐规则与挥拍候选 → 特征/评分 → 服务端结果 → 前端报告。

- `src/rallymate_vision/pipeline.py`、`pose/adapters.py`：真实视频与姿态推理；当前本机预设是 RTMPose M、Halpe26。
- `src/rallymate_scoring/stroke_candidates.py`、`stroke_analysis.py`：当前主要依赖时序规则；不等于已经训练过网球分类器。
- `src/rallymate_service/training_evaluation.py`、`user_demo.py`：参考评价、服务端聚合结果。
- `src/rallymate_scoring/rotation_analysis.py`：二维转体连续段和逐指标证据。
- `src/rallymate_service/footwork_review.py`：逐段步伐复核。
- `src/rallymate_features/coordinates.py`、`temporal.py` 和 `src/rallymate_vision/camera_motion.py`、`timebase.py`：等尺度坐标、真实时间轴、相机补偿，不得因评分重构回退。
- `scoring-demo-web/app/ScoreLab.tsx`、`LiveResults.tsx` 和相关 panels：现有页面；`app/lib/measurement-evidence.ts`、`report-export.ts`：展示/导入/导出语义。

此前只读审计发现：某真实视频的姿态覆盖已经很高，但多个挥拍候选仍无法分类；关键障碍包括固定二维方向规则、全局持拍手投票、多指标共用全局缺证据状态。姿态置信度/覆盖不是识别或评分准确率，换大模型不会自动解决后续规则。

改造时分开处理：动作未分类、视角不支持某项测量、具体关节遮挡、镜头补偿失败、质量分未标定。一个维度缺失不应连带清空可独立测量的其他维度；“待复核”不能作为所有成功结果的统一结论。依然要保留真实缺测，禁止放宽门槛来制造分数。

## 已选定的开源参考与使用方式

以下是方法/组件选型，不表示对应网球模型已安装、训练或接入。

1. [MMAction2](https://github.com/open-mmlab/mmaction2)：参考其可替换的时序动作识别、骨架序列输入与模型适配流程。先定义关节映射、连续时间采样、缺测掩码、主体身份和动作阶段接口，再隔离评估 ST-GCN/PoseC3D 等候选。现有预训练类别不自动对应网球动作，不能把接了接口写成已具备分类精度。代码 Apache-2.0；实际复用时锁定来源版本并保留声明。
2. [FineDiving](https://github.com/xujinglin/FineDiving)：借鉴阶段划分、对应阶段比较及质量预测流程。网球可按准备/引拍/击球窗口/随挥/恢复组织；需要区分动作候选中心和已确认触球。代码 MIT，数据集有单独申请条款；不直接把跳水权重当网球评分器。
3. [Fitness-AQA](https://github.com/ParitoshParmar/Fitness-AQA)：借鉴具体动作错误识别、按错误解释建议。先建立步伐和转体的错误定义、可观测条件及验证样例。其数据集注明非商业用途，未经许可不直接纳入本项目数据。
4. [CoRe](https://github.com/yuxumin/CoRe)：后续有教练标注后借鉴同类动作与有分数参考视频比较的方法。当前不把普通骨架相似度改名为技术分；代码复用前重新核验许可。
5. [tennis-tracking](https://github.com/ArtLabss/tennis-tracking)：球路模块参考 TrackNet 时序轨迹、球场与落点关联流程；代码 Unlicense，模型权重另查条款。正式比赛画面上的表现不能直接推广到手机随拍。保留当前跨 ID 300 ms 与方向余弦 0.7 约束，修改前要有对照验证。

不直接移植 SkillEye 的模板百分分：作者缺少教练评分真值，其无可比模板回退 50 分的行为不应进入本项目。Tennis-Serve-Analysis 显示随机球速的实现也不作为可靠测量参考。

## 新分支开发顺序与验收

1. 先读实际代码与上述文件，留存现有私有样本的指标基线，明确分辨率/画幅、机位、身体像素高度、帧率等分层。公开提交不包含用户视频、任务库、原始任务结果或凭据。
2. 打通“视频规格与视角适用性 → 主体连续片段 → 动作与阶段 → 单指标测量 → 参考/技术评价 → 建议”的分层路径。给每项输出明确数值、单位、适用范围、原因、时间段和来源版本。优先改进步伐与转体。
3. 在可运行流程中实现逐项降级与阶段对应，建立可替换的时序识别后端。新增模型放隔离环境，保留现有推理环境；无合适网球权重时如实记录规则基线，不伪称完成模型训练。
4. 完整重构前端信息层级：上传/分析进度清晰；训练报告首屏简洁；动作时间线可定位回放；步伐与转体分项可展开；测量细节、公式和诊断默认折叠。保留新视频上传、历史结果、重试、导入导出、移动端可用性。
5. 针对变化做有效回归：尺度/画幅不变性、时间缺口、不同机位适用性、局部遮挡不清空独立指标、空证据不造分、参考分与技术分分离、接口/报告一致、回放定位。用真实本机样本验证上传到报告链路；算法准确率必须另有独立真值，单元测试通过不代表评分正确。
6. 在新分支持续完成实现与验证。缺教练标注、需要付费算力、使用限制不明的资源或产品方向变化时问用户；常规本地修改和测试自主推进。

- `scripts/start_local.ps1 -Build` 构建并启动本机服务；`scripts/full_service_status.ps1` 检查认证就绪接口。服务运行时不要直接覆盖前端 dist 后不重启，这曾导致旧资源清单和上传页面失效。API 内嵌一个 GPU worker，不要重复启动；不要直接使用默认监听所有网卡的 `run_full_service.ps1` 代替本地入口。

- 新对话使用同一项目目录；新旧分支共享忽略提交的 `runtime`、`service_data`、模型与前端构建目录。切分支不会自动更新运行中的 API/Web，验证时须确认服务加载的源码与构建版本。
