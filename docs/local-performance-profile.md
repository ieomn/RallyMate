# 本机持久性能配置

本机 SAM DINOv3 的运行配置保存于 `config/local-performance.json`。这是非秘密、版本化的配置文件；`.codex_tmp/full-service/launch-profile.json` 仅是某次启动的回执，不能作为下次启动的配置源。

当前接受的本机配置为 RTX 5070 Ti、至少 15000 MiB 显存，SAM 帧批次 8、主体上限 8、额外批图 8、完整 decoder 批图 8、forward/head 图预算 2560/512 MiB、准备和推理重叠、归档队列 8、三维准备线程 2、上传块 1 MiB。通用 Python 库的默认值和 RTMPose/ViT-H 的启动方式保持独立。

`start_local.ps1`、`restart_preview_service.ps1` 和在 SAM DINOv3 环境中运行的 `run_full_service.ps1` 均加载此配置。普通启动不会因为新 PowerShell 没有旧环境变量而回退到 batch1。缺失、损坏、非法配置或批量运行所选 GPU 不符合硬件范围时，启动会明确失败；重启入口在停止旧服务之前执行校验。

参数优先级为专用启动脚本的显式参数、进程环境变量、持久配置。未指定的专用脚本选项保留现有配置。`restart_performance_preview.ps1` 成功启动后，会原子保存本次完整配置，普通重启继续使用它；若安全检查拒绝重启，不会保存修改。显式单帧基线会关闭继承的额外批图；显式空 decoder 批图也能穿过 Windows 的空环境变量语义。非法或互相矛盾的组合会报错。

启动回执记录时间、API launcher PID、配置路径与 SHA256、本次继承的性能参数及来源。它只证明启动环境，不代替模型就绪、实际批执行记录或端到端性能验收。没有记录鉴权密钥或完整进程环境。性能脚本中的进程变量会在返回时还原，而配置文件会保留。

启动器拒绝占用端口的重复启动，且在覆盖旧日志之前将 API、前端日志和旧回执复制到 `.codex_tmp/full-service/startup-backup-*`。指定启动隧道时也保存旧隧道日志。

受监管服务重启时先请求仅限内部鉴权和本机访问的 `/internal/maintenance/stop-executor`。API 原子暂停新任务接收，忙碌时拒绝维护；执行器只在安全循环边界退出，不取消当前计算。脚本必须等到健康响应明确确认 `maintenance=true`、空队列和 `executor.status=stopped`，才重新捕获进程快照并清理 API/前端。等待超过 50 秒时停止重启操作，绝不强杀；接收暂停仍保留，可检查状态后重试。这样既不会让监管器在清理过程中重生子进程，也能让 GPU 所有权标记正常清理。

首次从旧服务迁移时，只有维护接口返回 404、旧健康检查 ready 且空队列、没有 executor 字段、所属进程树没有新监管 worker 时，才允许旧式清理。无论新旧路径，都拒绝仍有所属三维渲染子进程的情况。不能把 API 在线或分析任务 succeeded 当成可以中断三维的依据。

## 执行器监管的覆盖范围

本机监管器覆盖的是**监管父进程仍存活时，执行器子进程退出**的恢复：先确认整个所属进程树退出，再清理对应 GPU 所有者标记，只恢复同一 owner/attempt 的未完成任务，随后重新启动执行器。每个监管器生命周期最多自动重启 3 次；任务自身还受 `max_attempts` 限制，取消请求优先于重试。普通业务异常已将任务标记为 failed、但执行器仍活着时，不会被这条机制自动重新推理。每次启动的日志独立保存在 `service_data/executor-logs/`。

心跳约每 2 秒更新，独立于处理帧数。超过 30 秒未收到有效心跳时，健康检查报告执行器不可用并暂停新提交；已有任务和报告仍可读取。监管器不会仅因进度不变、心跳延迟或租约过期而杀进程、重置任务或重复推理。因此，仍存活但卡死的执行器、GPU/驱动挂起和磁盘故障没有得到自动恢复保证，需要进一步诊断。

**父 API/监管进程突然崩溃、被强制结束或机器重启，不属于上述自动接管范围。** Windows 的所属 Job Object 会在所有者退出时终止其子树，但新监管器没有旧实例的完整退出确认回执；节点持久 GPU 标记和受保护的 `fleet-` 任务记录可能保留。当前启动会拒绝不明确的所有权，不能把重新开机或 API 又上线当成任务已经恢复。此时需核对旧 owner、attempt、日志和实际退出证据，再按已确认退出的恢复流程处理；没有实现自动开机修复。不得仅凭旧 PID 不存在、文件较旧或租约超时删除标记、重置任务。相关所有权约束见 [GPU 运行指南](gpu-fleet-operations-20261107.md)。

普通脚本重启走前述维护 drain 流程；它与直接结束终端、杀进程或重启机器不同。普通重启验证通过，以及完整视频一次运行成功，都不能扩展成“所有故障均可自动恢复”的结论。

离线验证：`powershell -NoProfile -ExecutionPolicy Bypass -File tests/test_local_performance_profile.ps1`。测试在独立临时目录执行真实普通启动脚本，替换所有进程创建和端口查询，覆盖两次清空环境后的启动、保存后重新读取、非法配置拒绝、硬件容量校验、日志保留和三维子进程保护，不启动服务或 GPU。
