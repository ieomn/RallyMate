# SAM 资源调度与 Mesh 续作

本分支优化现有 SAM 3D Body 的内存复用、原帧批量调度、几何写盘和后台回放。模型权重、推理精度、关键点定义及评分规则保持原有配置。生产基础配置的批次仍为 1；已有本地性能配置选择的 batch 8 继续由该配置管理。

## 推理与结果写盘

批量 GPU→CPU 输出、CUDA 缓存复用和内部阶段计时现在可以同时启用。计时器跟随实际 estimator 方法使用的 globals，包括输出传输优化创建的实例副本，并在正常退出和异常退出时恢复。锁页内存和 CUDA Event 的原有完成等待保留，CPU 消费者收到的是传输完成的数组。

隔离 SAM 进程默认保留可复用的 CUDA 分配器缓存，停止逐帧清空；进程关闭时继续释放缓存。显式设置 `RALLYMATE_SAM3D_REUSE_CUDA_CACHE=0` 可复现逐次清空策略。

首次 NPZ 生成、拓扑校验和哈希计算交给单个后台线程。该线程最多保留两组、64 MiB 自有 CPU 数组快照，超过预算时产生背压。快照保留原数组的 dtype 和数值，后续推理复用输出内存不会覆盖正在写盘的数据。写盘失败清除该组已经生成的临时 NPZ；取消、异常和进程关闭都会处理已提交任务。

后台写盘与同一请求内后续主体或后续 GPU 分组重叠。IPC 返回前等待所有相关文件就绪，因此文件消费者继续遵守原来的读取约定。单主体、单分组请求没有后续 GPU 工作可与写盘重叠；父子进程仍按单请求在途管理共享像素内存。

原生记录中的 `mesh_capture_timing` 分别记录提交与背压时间、后台写盘时间和请求结束处的等待。多个主体共享一组计时。`inference_ms` 不包含请求末尾的写盘等待，前后性能比较使用完整 IPC/request 墙钟或完整流水线墙钟。

## 批量缓冲与观测

未指定源帧预算时，SAM 暂存预算为 `min(256 MiB, max(64 MiB, 已观察到的最大单帧字节数 × 请求帧数))`。多帧请求与 IPC 的 256 MiB 上限保持一致。8 张 3840×2160 的 uint8 BGR 原图共 199,065,600 bytes，可以构成一个八帧请求。单张原图大于暂存预算时单独发送，并记录 `oversized_single_frames`，沿用已有单帧路径的传输校验。准备队列、IPC 共享内存和 GPU 内存各自保留独立边界；该源帧预算不代表整个进程的内存上限。

`processing.sam_pose_batch` 新增实际帧数直方图、选中主体数直方图、批次填充率和刷出原因。选中主体数是提交给 adapter 的候选数；真实 GPU 分组大小以原生记录中的 `batch_execution.subjects` 为准。`flush_reasons` 区分达到请求帧数、达到原帧字节预算和视频尾部。

CUDA Graph 的计数按执行路径解释。完整 decoder graph 接管 body head 时，body head 的零 replay 与 fallback 计数不能单独说明整个请求执行了 eager 路径；同时查看完整 decoder、forward graph 和真实主体批次。

## 后台回放

回放以完整编码段保存检查点，默认每段 60 个选中帧。公平轮转默认给出 15 秒时间片，在完成一个段后检查时间片；持续有排队分析任务时，每次轮转仍能保存至少一段。正在运行的推理、任务取消和服务停止继续触发抢占。尚未完成的段重新生成，已完成的段从检查点恢复。

检查点绑定源视频、几何账本、渲染实现、模型标识、选择区间、画面尺寸和编码参数。恢复时校验段文件。连续段共享顺序解码器、OpenGL 渲染器和拓扑缓存，跨轮转通过上一段末帧的精确 PTS 定位；源视频哈希在每轮开始和结束检查。最终用已编码 H.264 包拼接，并逐帧验证输出 PTS，不增加二次视频编码。

成品完成后，检查点转为完成回执，绑定最终结果与媒体哈希，再回收已生成的分段视频。清理只删除受管目录中校验通过的已知文件。文件占用等清理错误保留成品的 ready 状态，并记录缓存保留情况；再次进入时验证成品、重试清理，不重新执行解码或渲染。未完成或被取消的回放继续保留可恢复的段。

## 参数与基准

| 参数 | 默认行为 | 用途 |
| --- | --- | --- |
| `RALLYMATE_SAM3D_REUSE_CUDA_CACHE` | 隔离进程为 `1` | 复用 CUDA 分配器缓存；`0` 用于对照 |
| `RALLYMATE_SAM3D_PROFILE_STAGES` | `0` | 开启内部阶段及 CUDA Event 计时 |
| `RALLYMATE_SAM3D_ASYNC_MESH_CAPTURE` | `1` | 有界后台首次 NPZ 写盘；`0` 为同步写盘 |
| `RALLYMATE_SAM3D_SOURCE_BUFFER_MIB` | 按帧尺寸计算 | 显式指定 `1..256` MiB 原帧预算 |
| `RALLYMATE_SAM3D_MESH_SEGMENT_FRAMES` | `60` | 每个保存段的选中帧数，范围 `1..1800` |
| `RALLYMATE_SAM3D_MESH_TIME_SLICE_SECONDS` | `15` | 公平轮转时间片，在完整段边界让出 |

两个现有基准脚本均接受 `--reuse-cuda-cache`、`--profile-stages` 和 `--async-mesh-capture`，取值为 `0` 或 `1`，显式参数优先于环境。实际配置保存在报告的 `worker_profile` 中。预热阶段使用与生产暂存一致的帧尺寸预算，覆盖高分辨率八帧请求。

建议在同一连续视频窗口、相同人物框、相同批次配置下分别测量调度开关，保留完整关键点与网格比较结果。模型加载、预热、产物比较和正式计时分别记录。Nsight 时间线在预热完成后采集 30–60 秒，同时保留 summary、原生 SAM 记录和 Mesh manifest。

## 本次证据范围

现有最近完整运行处理 13,116 帧、分辨率 960×448，流水线墙钟 648.835 秒，姿态阶段 380.632 秒，独立 Mesh 渲染 156.687 秒。该运行实际峰值为 8 帧，源帧占用 10,321,920 bytes，未触发 64 MiB 缓冲截断。这些数值描述修改前已有运行，不是本分支的加速结果。

单元和进程测试覆盖高分辨率批次、原帧/PTS/主体顺序、缓存与计时组合、后台写盘背压、失败及取消清理、检查点恢复、源文件变化拒绝和 H.264 拼接。另一次真实 CUDA 小张量检查使用合成 estimator，验证了锁页输出、CUDA Event 完成等待、FP32/FP64/int64 数值与布局、异常恢复和跨线程结果读取，共 17 项检查通过；该检查不加载 SAM 权重。

最终综合回归运行 538 项：527 项通过，11 项因主业务 Python 缺少 RoMa 依赖跳过。随后在隔离 SAM Python 中运行完整 RoMa 测试文件，13 项全部通过，覆盖前述 11 项。最后增加的分段媒体篡改清理回归也通过。PowerShell 启动配置测试在 5.1 和 7.6 两个环境中各通过 36 项断言，使用模拟进程；代码差异检查通过。

本轮未重启常驻服务，未采集新的完整模型前后对照或预热后 Nsight 时间线。现有服务继续使用启动时加载的代码；新进程启动后加载分支实现。
