## 评分计算与结果契约

`action_aggregation.py` 提供共用汇总函数。一个动作片段内的有效指标先形成维度分，同一维度的有效片段等权；总体分继续由可用维度等权计算。输出的指标权重可以复算维度结果。布尔值、非有限数值、越界分数和缺少实际测量的指标不参与评分，同一指标不能重复归入多个维度。

等级适配器复用这套测量读取和片段均分逻辑，通过 `movement` 维度 ID 获取支撑分。明确识别的技术进入子技术汇总，尚未细分的动作进入类别汇总。被排除的另一种反手或当前等级权重为零的技术，不再通过类别分回退进入总分。未知发球旋转子类仍保留已观察的发球动作分，不复制成多个子技术。

模型评分证据与实际几何测量逐项对照：视频 SHA、人物、选择时期、相机时期、原帧和 PTS 时钟必须一致。精确 PTS 换算时间和取整后的显示时间分别保存、分别校验，小数帧率及非零原始时间起点可以正确传递。

旧指标事件的 `person_track_id` 表示规范主球员，模型窗口中的同名字段表示原始检测轨迹。指标评分调用链显式传递两者的映射，依据事件自身的轨迹诊断和已验证窗口核对身份，保存后的指标记录可以按同一规则批量重算。映射不从待评分特征反推，也不因编号为 1 而放行。

前端接收器读取相同的权重版本，接受原文未启用模块的空权重，并核对默认配置、反手路线、覆盖率与汇总结果。动作指标跨维度重复、漏入汇总，或者动作记录与评分有效性记录的轨迹和时间窗不一致时，接收器拒绝该报告。报告导出与重新导入保持合法指标数值和总分。

历史导出按报告声明的版本校验。只读 `level_grading_legacy_v1.json` 保存起点提交的 v1 配置，历史分数按原权重读取；新评分统一使用 v2。未知版本或冒用另一版本的权重会被拒绝。历史配置文件的 SHA-256 为 `1f58c8320022083f2f24b93ad63b189405505b6d958c7afdad507f859dbccd07`。

模型置信度独立于动作分。未知置信度保持 `null`；实际特征有效且有数学规则时计算分数，缺少数学规则时保留测量。动作阈值的来源仍是版本化工程规则，`coach_calibrated` 保持 `false`。

## 复验入口

在本分支根目录执行后端集中回归。运行环境需要项目 Python 依赖；命令不加载模型执行推理。

```powershell
$env:PYTHONPATH = Join-Path (Get-Location) 'src'
python scripts/validate_scoring_regression.py
```

前端依赖安装在当前工作区，随后执行：

```powershell
npm.cmd --prefix scoring-demo-web ci
npm.cmd --prefix scoring-demo-web run typecheck
npm.cmd --prefix scoring-demo-web run lint
npm.cmd --prefix scoring-demo-web run build
$env:PYTHON = 'python'
Set-Location scoring-demo-web
node --test tests/*.test.mjs
```

前端少量历史真实报告测试使用本地私有样本。其文件路径由测试显式检查；没有相应文件时，测试记录跳过。正式卡片历史回放测试通过 `FORMAL_V2_REPORT` 指定独立报告。

完整视频复验使用当前评分源码重新计算已有完整推理的产物，并核对视频 SHA、原帧范围与原生姿态记录。参数分别指向本地视频、任务数据库和输出目录：

```powershell
python scripts/validate_full_test_scoring.py --input FULL-TEST --database service_data/jobs.sqlite3 --output reports/scoring-refactor-20261112 --evaluate
Set-Location scoring-demo-web
node scripts/validate-full-test-scoring.mjs ../reports/scoring-refactor-20261112
```

这条命令没有提供 `--submit-missing`，复验只读取已有推理记录。后端回执保存源码指纹、逐视频检查和失败明细；前端回执逐份检查报告的总分、动作数量、关节测量与五级结果。私有视频、任务编号和运行报告保留在本地，不随代码提交。
