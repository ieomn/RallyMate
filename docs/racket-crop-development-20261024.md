# ATP 左手动作漏检的局部球拍检测实验

在已观察的 ATP Rome 2019 原片段 8.000–31.000 秒上，对全部 575 个原帧执行了一次新的 YOLO26n 球拍检测。固定方案在推理前保存：按原选人框中心裁正方形，边长为原框较大边的两倍，越界仅裁至原图边缘；640 输入、CPU、球拍类别 38、置信度 0.25、IoU 0.7，使用原本的检测权重。没有按八个人工动作窗选择推理帧，没有调整原候选识别阈值，也没有重做姿态推理。

来源仍是 [ATP Tour 官方 Rome 2019 视频](https://www.youtube.com/watch?v=W8JJJ2j5hOM)。该片已用于开发，不能再作为未见保留集。本实验没有新增视频、专家标签或评分卡实例。

新检测在 70 帧给出 73 个球拍框。局部框按裁剪原点精确加回原图坐标后，与原观测一同送入未改阈值的击球候选计算。原路与加入新框的路径均为 0 个候选，八个人工可见动作仍全部漏掉（六次正手、两次双反）。没有候选时精确率分母为零，保留 null。球拍框数量不能解释为确认持拍、真实击球或已修复漏检。

在原注释窗两端各扩 500 ms 的只读诊断中，六个正手邻域左腕球拍支持从 `[1,0,0,0,0,0]` 变成 `[1,3,1,0,0,0]`。这说明放大仅补回少量局部观测；即使某个较宽诊断邻域有三帧支持，也不保证同一合格运动子窗同时满足连续性、手腕路径和球拍门槛。该方案尚不足以作为修复这批动作漏检的生产兜底。

全帧补充观测保存在 `tests/fixtures/racket-crop-development-atp-20261024.json`，包含真实 PTS、原选人框、裁剪框、局部和原图检测坐标、来源摘要及冻结方案。原始视频和 frames/primary 文件保留于本地忽略目录，未覆盖。Git 源码基线为 `7da25727faa04dfb4f213cec50e57aabf911a76c`；实验目录 `.codex_tmp/racket-crop-feasibility-20261024` 的 `probe.py` 和 `finalize.py` 摘要存于 fixture。原推理程序在输出完整观测及两份候选结果后，因 Windows Git 路径分隔符导致最后收据导出失败；后续进程核验了全部 227 个归档源码文件，重放候选与已保存输出完全相同。没有把恢复收据称为第二次模型推理。首次环境尝试缺少 PyAV，实际推理使用 OpenCV 顺序读取及 FFmpeg 实际解码 PTS。

`replay_summary_sha256` 在打包重放时另行捕获，用于核对 source job；不声称该 summary 是此前模型推理的输入。重放入口要求 video、模型、原 manifest、frames 和 primary 的摘要完整，逐帧核对 source/processed 顺序、原 PTS、身份与裁剪坐标，不接受删除漏检帧、布尔索引或错绑原点。识别结果只反映这一实验，始终无技术等级和卡片分数。

在包含已提交代码的干净目录中，可用以下命令重新解码原视频、校验保存的补充检测并重新计算动作候选；不会重新运行 YOLO：

```powershell
python -B scripts/replay_racket_crop_feasibility.py --artifact-root <原始资产根目录> --output <不存在的新报告.json>
```

测试入口为 `python -B -m unittest tests.test_racket_crop_feasibility -v`。设置 `CARD_ARTIFACT_ROOT` 可执行真实媒体检查；未设置时该项明确跳过，合成来源反例不算新视频。
