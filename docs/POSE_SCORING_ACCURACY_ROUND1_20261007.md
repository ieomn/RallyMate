# 姿态与评分可信度：第一轮修复（2026-10-07）

本轮从 `codex/pose-scoring-accuracy` 的 `d5b4870` 开始。改动只在开发分支，未合入 main。范围是已有姿态产物的 CPU 诊断、原文测量身份门禁和人工真值接收验证，不是新的姿态准确率或技术评分标定。

## 可复现问题与处理

1. **原文测量漏掉人物身份失败。** 原事件携带 `confirmed_id_switch_present` 时，既有指标质量门禁已禁止测量，但原文测量路径仍可能返回数值。最小复现的 FS01 事件有七个子测量错误地保持 `measured`。此外，将实际测量窗口内一帧的主球员设为未选定或改为另一源轨迹，踝距/髋宽与速度波动仍可返回数值。

   `source-aligned-fs-measurements-v1.1.0` 复用现有质量规则，并对传入人物时间线的实际测量窗口逐帧核对人物、源轨迹、时间和选择状态。身份失败返回 `value=null`、`status=unavailable`，API 返回中文解释；跳点或左右交换**候选**不被冒充为已经确认的失败。旧调用方未传时间线时仍使用既有事件诊断契约，不能据此声称增加了独立身份真值。旧文件不回填覆盖。

2. **导数跨越遮挡或未采样区间。** 既有导数使用前后有限值，即使中间姿态缺失也可能连接。例如两段分别静止但位置不同的足踝，在遮挡前后被计算出速度。新增 `contiguous_irregular_derivative` 候选只在连续有限样本间求导；160 ms 上限沿用现有连续观测工程约束，不是新增评分阈值。孤立观测保持 NaN，连续序列与原算法精确一致。

   候选有独立版本，使用固定保存事件边界的 CPU 对比入口。**当前生产导数、事件算法与已发布注册表未切换**：正式启用还需新注册表/特征版本发布、边界与质量影响验证。对比只说明计算差异，不能说明哪种估计更接近真人真值。

   12 条保存视频的 30,746 帧、1,521 个事件重放用时约 17.09 秒，107 个事件有差异，合计 1,695 个“事件×关节×模式×帧”变化（原观测 1,529，既有平滑结果 166）。例如任务 `eff73d13-3eba-4f37-abb9-c51226bec8e3` 的 `fs02-000-7e4800a29456`，右踝 7.467 秒处旧导数跨越 7.433→7.600 秒缺测，图像速度分量为 `[0.745132, -0.243578]`；候选只用连续片段，得到 `[0.058471, -0.002719]`，单位为画面长边/秒。数值不同不等于候选误差已经更小。

3. **真实标定输入缺少公开验证入口。** 新增只读 `verify_scoring_truth_calibration_intake`：重放 M93 A/B/C 事件裁决链和原始 CSV 真值 intake，再核对由受控配置提供、SHA 固定的独立接受账本。持久化字典、模板、自填批准字段和本地事件标注放行均不能单独获得标定输入权限。参见 [授权接收验证说明](SCORING_TRUTH_AUTHORIZED_INTAKE.md)。本轮没有签发真实接受记录、标定资产或生产评分权限。

4. **本机测量来源 latest 指向过时版本。** 基线 `test_calibration_measurement_sources` 因旧清单绑定 `pose-wave-2026-08-22.17` 而拒绝当前注册表，属于正确的来源校验。旧清单的注册表 SHA 为 `E6B7C3A05DA08A7BC96821DE3662113111653E10EC46D20A037578AD3F6E3305`，不能重算替换。

   核对三个视频的原视频、帧、原姿态摘要、人物时间线和摘要哈希后，用现有 builder 重放 15,868 帧，新建本地来源集 `halpe26-m256-primary-v0.3-registry-20261001-2-replay-20261007-v1`，再更新本地 latest。旧清单原字节保留；新清单绑定当前注册表 SHA `DC5F3622D70F22AD5DA8E933DCD38E7D8C4C57FD5255941FA521704984FEAC0E`。没有 GPU 推理、人工标签或 F3/F4 晋级。

## 复现入口

从仓库根目录在 PowerShell 运行：

```powershell
$env:PYTHONPATH = "$PWD\src;$PWD\tests"
$py = "$PWD\runtime\rtmpose\.venv\Scripts\python.exe"
& $py scripts/build_technical_review_rules.py --check
& $py -m unittest test_source_aligned_features test_source_assessment test_source_assessment_backfill
& $py -m unittest test_kinematic_continuity
& $py -m rallymate_evaluation.kinematic_continuity `
  --run-dir <含frames.jsonl、primary-player.jsonl、events.jsonl的已保存目录> `
  --output <新的诊断JSON路径>
```

诊断拒绝覆盖现有文件，并绑定输入原始字节 SHA；固定边界、原始观测与既有平滑序列分别比较。输出的图像速度不是正式身体尺度特征，也不是技术分。事件重叠导致相同样本可能重复计数，不能把变化计数当独立错误帧数。

本机基线与日志保存在忽略目录 `.codex_tmp/pose-scoring-accuracy-20261007/`。最初来源/评分/真值定向基线为 91 项通过；API/Schema/注册表基线为 47 项通过。标定基线最初 114 项中有一项来源清单初始化错误；新来源集生成后该模块四项通过。测试只证明软件行为和来源约束，不证明姿态准确率。
