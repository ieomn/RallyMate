# 原人物框约束的姿态关联

版本：`pose-person-geometric-association-v1.0.0`。这是同一原帧内的几何关联政策，不是网球技术阈值，也不证明人的身份或换人真值。

## 根因及固定政策

旧 YOLO ROI 后端在每个扩张人物框内选择人物框置信度最大值，再由适配器赋予原人物 track。两个 ROI 重叠时，这会把同一背景人的姿态赋给两个 track。USTA 原帧 11986 是实际反例；它的所有必要关节置信度很高，单独检查置信度、primary 标签或选择 epoch 不能发现错误。

`infer_targeted(rois, target_boxes_xyxy, *, timestamps_ms=None)` 接收与 ROI 一一对应的原 detector 人物框，坐标是 ROI 内像素。只按候选框与该目标框 IoU 选择：最大 IoU 至少 0.5，且领先第二名至少 0.1（浮点比较容差 1e-12）。这两个工程关联门槛在修复回放前固定，不按视频成败调节。置信度不用于打破几何歧义。非有限、非正面积、越出 ROI 的框、候选数组错位、缺关节置信度都拒绝，不裁剪或补置信度。

保留旧 `infer` 接口；无目标的 YOLO 调用仅允许一个候选，多候选返回空槽。可选能力不向 RTMPose 等旧后端强加新参数。输出槽数与目标数必须严格一致。适配器将选中框变回原图坐标，再与全部原人物检测框比较，包含因 `max_players` 未推理的人物。只有原目标具有上述唯一 IoU 归属时才发布姿态。重复/非法原 track ID、非法原人物框不进入推理。

`PoseBackendOutput` 新增可选 `person_bbox_xyxy` 与 `person_association`；接受的目标输出保留原人物框、候选框及几何选择证据。YOLO 元数据写入 `person_association_policy_version`。其他后端的空版本字段不序列化，旧元数据保持兼容。

## 旧原帧的纯几何冲突检查

`audit_pose_person_associations(poses, player_detections, *, frame_size=(width, height))` 不调用模型。输入必须是同一帧、`original_frame` 像素坐标的姿态字典，以及该帧已筛为 player 的原检测字典。调用方负责附原 frame/PTS、选择人与输入文件来源；该函数不跨帧猜身份，也不使用速度。

两不同 track 的左/右肩、左/右髋、左/右踝六个同名关节，必须全部有限、在原图内、置信度至少 0.35。六对距离必须分别不超过 `max(2 px, 0.05 × 两姿态中较小的肩髋长度)`，才形成 `pose_duplicate_body_different_tracks` 冲突。该容限是像素重推理差异的工程政策，不是“快速移动”阈值。必要关节缺失时记录 `unassessed_person_track_ids`，不能把无裁决叫作已证实安全。缺原图尺寸返回 `status=unavailable`，不猜尺寸。

重复成立后，高置信关节包围框与所有原人物检测框的 IoU 仅作归属辅证。若两套重复姿态都唯一匹配同一个参与 track，保留该 track、拒绝另一个；无法唯一定位时拒绝双方。输出保存六个距离、容限、肩髋长度、两几何框、每个原人物框 IoU、建议归属和被拒绝 IDs。源消费者必须按所选原 track 与实际窗口检查，不得将其他人/窗外冲突扩散成全视频失败。

这是一项充分冲突检查，不保证发现所有错配：缺六个高置信关节、并非近重复的错误姿态、未检测到的另一个人体仍可能无裁决。原检测框自身也不是专家身份标签。没有把“不冲突”提升为身份真值。

## 实际三帧与可移植测试

`tests/fixtures/pose-association-usta-11986-v1.json` 保留原 run `extension-fs-usta-return-footwork-heldout` 的 11985/11986/11987 三帧完整 raw/primary 记录和各原 JSONL 行 SHA，四个原文件 SHA、视频/权重 SHA、实际 FFmpeg PTS 与原 PNG SHA。另存同权重、同 CPU/imgsz640/conf0.25/ROI margin0.15 下实际重新推理的六个 ROI、全部十三个 post-NMS 候选及原输出。原重放生产源码为 `3e142c6`；本修复干净基础为 `19f1f25`，这三个原 pose 文件内容相同。没有重跑 detector，也没有改写旧 raw。

保存候选的确定性单元回放不是新模型执行：旧六个输出先已与原 raw 逐字段相等，再用新选择路径重新评价这些候选。11985 与 11987 的四个人物输出保留原数值；11986 的教练输出也保留。11986 女孩 ROI 有两个女孩候选，目标 IoU 为 0.653824 和 0.679764，差 0.025940，按固定政策拒绝歧义；旧置信度 argmax 取的是教练（目标 IoU 0.364953）。不能删去一个候选以产生正例。

旧 raw 三帧审计分别拒绝 `[] / [2] / []`。11986 六个同名关节差 0.65–2.58 px，容限约 4.76 px；两姿态几何框分别与教练原框 IoU 0.714/0.673，与女孩仅 0.325/0.307。11987 教练脚部不全，保留“未充分检查”，不补点。这些证据说明同帧人体几何冲突，不宣称发生 track switch。11970–11996 旧候选窗必须保留这次缺失，不平滑、跨点或扩窗取分。

专项测试覆盖高置信错误候选、同人多候选歧义、无目标多候选、非法框、数组错位、未推理竞争人物、跨 ROI 重复、缺关节/缺尺寸、原三帧反例与两侧对照，以及旧非 targeted 接口。所有合成框仅验证数学边界。

最终另在干净 `19f1f25 + 本补丁四源` 中，按原视频实际解码并用同权重真实重跑六个 ROI：十三个 post-NMS 候选与旧探针逐字段相等，五个保留输出除新增关联证据外与旧输出完全相同，11986 的 track 2 没有输出或替代姿态。四个原数据文件执行前后 SHA 相等。实际模型运行的全部模块 SHA、输入 SHA、候选、诊断和解码依据记录在交付 manifest 引用的独立 receipt 中。这是已知失败的开发回归，不是留出验证；几何关联容限尚无跨视频误拒率校准结论。

## 诊断边界

空槽不会伪造姿态对象。`YoloPoseBackend.last_association_diagnostics` 保留逐 ROI 的候选和拒绝理由；`PoseEstimator.last_association_diagnostics` 保留原 track、原框、ROI、后端诊断及整帧 duplicate audit。接受的姿态保存自身 `person_association`。本核心补丁不修改已有大量工作区改动的 `inference.py`；若使用当前只返回 poses 的上层调用，完整拒绝日志需由调用方显式持久化。已存原数据可由纯审计函数重新检查，无需替换旧记录。
