# 评分逻辑与报告交付核查 2026 年 11 月 4 日

本次核对原始七份 Word、当前评分实现、任务数据库、近期报告缓存与保留的错误日志。结论是：原文目录和文本已完整登记，但当前自动百分制不是 Word 全项正式等级；部分无分来自观测不足，另有可复现的候选去重缺陷和报告资源诊断问题。本轮修复这些代码问题，不补造缺失证据或原文未给出的阈值。

## Word 对齐情况

- 原始七份 DOCX 的 SHA-256 均与登记来源一致。
- 直接读取 Word XML 复核 1,527 个单定位文本对象、8,462 个多定位文本对象、246 条视觉要求，没有文本差异；298 张 FS/GS 指标卡的构建校验通过。
- 298 张卡包括 50 张 FS 和 248 张 GS。当前编译规则分为 149 张视觉代理卡、149 张人工复核卡；规则进入目录不等于自动测量已实现。
- 原文仍有 3 张定义冲突、97 张缺少阶段边界；七份 Word 没有规定当前百分制换算、权重和可直接执行的 A–E 数值切点。

必须区分三种状态：任务 `succeeded` 表示视频处理与产物校验完成；五维 `scored` 表示五个维度各有可计分项目；原文正式评分需另查 `formal_scoring`、原卡判级和完整技术证据。近期五个缓存任务的原文自动判级均为 0，`full_source_technique_covered` 均为 false。

五维百分制采用工程试验阈值：先在每个动作内汇总同维度可测项目，再按动作等权汇总，总分按已测维度等权平均。缺测不计零分。因维内其余项目仍可计分，五维都有数值时也可能缺少引拍协同等项目。

兼容字段 `card_execution.summary.channels.formal` 和策略名称中虽然含 `formal`，实际语义为工程条件完成度，不能解释为 Word 原文 A–E 等级。保留协议字段与历史分数兼容，修正用户可见标签及说明。

## 历史视频为什么有分或无分

数据库统计时间范围为北京时间 2026-08-10 13:03 至 2026-11-03 11:26，共 128 个任务、50 个不同视频文件 SHA-256：121 成功、6 失败、1 取消。此统计包含重复分析和旧版本任务，不能作为当前评分准确率。

当前可复核的完整报告缓存共对应五个任务、四个不同文件 SHA，不能据此推断其余 123 个任务的当前五维覆盖。匿名样本情况如下：

- A 与 B：同一视频文件的两次任务，均为 85.71 分；23 个动作候选中接受 15、拒绝 8，报告分别约 52.10 MB 和 56.12 MB。15 个接受片段全部采用通用挥拍规则，未确认具体技术类型。
- C：82.79 分；19 个候选中接受 11、拒绝 8，报告约 80.67 MB。主姿态覆盖 94.15%，球观测 33.57%，球拍观测 62.23%。
- D 与 E：处理成功但五维无分，均为零挥拍候选，报告约 71.07 MB 和 71.00 MB，已成功生成并解析。二者文件 SHA 不同，但帧数与本次测量统计一致。

D/E 的 21,219 帧中，主球员未确认 16,321 帧；17 个映射关节有效覆盖均为 4,394/21,219，即 20.71%。球观测约 0.02%，球拍观测为 0。预览为远景，人物约 70 像素高；主要缺口是整个人物和姿态记录不可用，并非某个膝盖或手肘单独持续失效。

旧诊断中的 504 帧 `source_binding_mismatch` 实际对应 SAM 姿态质量拒绝；常见记录为人体投影倒置、时序投影突跳和投影超出人物框，多个原因可出现在同一帧。本轮细分为姿态质量未通过或原生姿态不可用，真正的来源不匹配仍单独保留。没有放宽几何检查以强行出分。

## 高频缺失环节

对 A/B 同源任务去重后，可评分样本为两个文件，共 42 个候选、26 个接受动作、16 个拒绝动作：

- 15/16 个拒绝动作缺可靠的阶段来源，另 1/16 个为持拍手竞争冲突。
- 26 个接受动作中，24 个采用通用规则，只有 2 个已验证为发球；不能把通用分数当作具体技术的完整评价。
- 在计入允许的指标替代后，24 个底线动作中有 12 个缺少 `preparation_sync`（引拍协同）。
- 26 个接受动作中有 5 个记录局部技术要求的阶段窗口不完整；接受整体动作不代表其中每个技术要求均可测。
- 两个发球均缺少独立前向/上向方向、真实受力/触地/重心、球拍触球/握拍、抛球释放/触球/触地的完整证据。这是两段发球的观测结果，不能外推全部视频。

## JSON 与任务失败

视频走二进制分块上传，当前默认块大小为 128 KiB。大 JSON 来自分析报告及逐项证据，不是把整个视频编码后塞进 JSON。

历史上确有大报告问题：一次传输日志显示展开证据达到 268,436,848 字节，超过当时 256 MiB 上限；一次 `MemoryError` 的保留栈指向旧 `write_scoring_loop_report → _load_jsonl(features_path)` 全量加载特征。当前工作区在本轮开始前已有证据池化、流式/SQLite 有界读取和报告持久缓存，应与本轮新修复区分。

现有报告限制为线缆传输 128 MiB、展开证据 512 MiB、400 万基础节点、2,048 个证明、20,000 个证明引用；报告准备上限 300 秒。本轮未提高这些限制。几十 MB 的报告仍会增加传输、浏览器解析和内存开销，JSON 本身不必然失败；应根据具体超限类型定位，不能将所有无分归为网络问题。D/E 的无分已能由姿态与候选证据解释。

六个历史任务失败包括两次 `float(list)` 类型错误、一次上述内存不足、一次请求重启后的中断、一次预加载模型不匹配、一次主球员时间线版本不匹配。两次类型错误未保留可定位源行的 traceback，不声称本轮已修复其根因。六个文件后续均有成功任务记录，但这不能证明所有旧问题永久消失。

## 本轮修复

1. **有效动作被重叠候选挡住。** 之前先按时间重叠过滤，再检查完整姿态，较早但无法计分的候选会遮蔽后续有效候选。现在仅通过完整来源与动作窗口校验的候选占用区间，并按人物与参考系区分；有效重复仍只算一次。回归用例在相同输入上从漏掉完整动作恢复为一段有效动作，评分公式不变。
2. **质量拒绝误报来源损坏。** 原生姿态被质量门槛拒绝或缺失时返回对应原因；已测量但来源不符的记录仍按来源错误处理。
3. **大报告构建中途缺乏预算检查。** 池化遍历中定期检查取消、时间和内存预算，避免等整个副本生成后才停止。
4. **报告超限被吞成通用失败。** 展开结构、证明数量、最终 JSON 大小超限返回 `413 report_delivery_limit`；内存或处理预算返回 `503 report_resource_limit`，延迟报告接口保留该分类。
5. **前端重复昂贵构建且掩盖原因。** 明确资源/容量超限不再自动连续重试，保留任务并提示原因；一般临时网络失败仍沿用原有有界重试。
6. **缺测与读取失败都显示为暂无结果。** 页面显示来源校验、读取失败、导入报告缺评分和后端无分原因；逐项列出未计分技术要求及原因。五维试验分、工程条件分与原文技术等级明确区分，分数不被改写。
7. **零候选也解析大型逐帧文件。** 没有动作候选且没有重新选人配置时，跳过无需参与计算的 `frames.jsonl` 解析，仍校验主时间线与原生姿态。真实无分任务复算约 3.206 秒，避免解析 255,429,918 字节文件，结果依然如实保留无分和具体原因；重新选人需要的重新识别路径保持有效。

这些修改不重新运行 GPU、不修改历史视频或数据库，不将缺证据补成零分、E 级或人为满分。修复后完整服务需要加载新代码；旧进程不会自动获得本轮逻辑。持久报告缓存包含源码内容指纹，服务重启后会避开旧构建版本缓存。

## 验证与可复核证据

前端相关测试覆盖候选结果展示、缺测原因、来源校验、读取生命周期、超限不重试、请求诊断和训练建议，123 项通过；逐卡面板与 HTML/Markdown 导出另有 44 项通过。TypeScript 类型检查及修改文件 ESLint 通过。后端评分与来源相关测试 150 项通过，报告传输、持久缓存、资源限制相关回归 82 个不同用例通过。这些是按模块的测试数量，未将可能重叠的验证重复加总为一个数字。

本地审计保留在 `.codex_tmp/word-source-audit-20261104.json`、`.codex_tmp/scoring-audit-20261104/history-audit.json` 和同目录只读脚本；真实任务复算结果保留在 `.codex_tmp/tennis-empty-real-recheck-20261104.json`。它们含本机任务与来源信息，不进入公开仓库。本文使用匿名样本，并明确统计分母。

后续若需要真正按全部 Word 要求自动判级，需要先补齐原文冲突与阶段边界、独立技术类别和触球/球拍证据，再以教练标注校准数值阈值。有候选的长视频目前仍会同时加载选中姿态与逐帧记录，资源预算是协作检查，不是操作系统硬内存隔离。进一步减少大报告风险应采用摘要与证据按需分页、分段加载，而非继续无限增大 JSON 上限。
