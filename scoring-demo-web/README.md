# RallyMate 网球训练空间

深色运动科技界面，主流程为训练总览 → 选片预览与拍摄自检 → 上传分析 → 查看观察与原片 → 保存关注点 → 下次继续训练。首次使用可先看 `/welcome/sample` 的虚构报告示例；示例明确不含真实分析结论或可播放原片。拍摄指南包含机位、完整入镜和遮挡示意。主产品不展示模拟分数；结果默认显示原视频，动作标记和球路均有常驻开关。

结果页常驻「原视频 · 动作识别」，通过动作标记辅助复看原片，保留慢放、动作片段定位和球场取图。白模与 AI 白模对比的产品入口、生成操作、轮询、前端代理和服务接口已移除；历史任务和视频文件仍保留。旧 `#motion-replay`、`#skeleton-replay` 链接会回到原视频。全身骨架连线已替换为手部短尾迹与脚部位置：只使用可靠观测，手部路径最多保留半秒，跨身份、漏检、时间断点及明显跳变时断开。脚部位置不代表真实触地，手部路径不代表球拍路径；不使用展示插值生成动作证据，不改变评分。SAM 3D Body 的 DINOv3 与 ViT-H 已接入本地推理和测量链，并直接渲染模型真实顶点及官方拓扑，提供淡蓝人体表面原片叠加与居中 90° 侧视。该预览在评分完成后后台生成，结果页通过轻量状态接口自动接入，同源视频逐帧 PTS 已核对；预览失败不会阻断评分。原片与关键点入口继续保留。

结果先呈现一至两个有依据的观察问题，说明看哪段、观察什么和下一步；可定位原片并保存为训练关注点。模型估计、待复核线索与缺少依据分别标明，不推断未经证实的动作错误。原片下方按需展开场地俯视图、训练指导五维图、测量详情和导出；问答位于深入查看之后。五维按原文阶段整理为移动质量、准备与引拍、挥拍协调、触球控制、随挥与衔接；这是展示分组，并非原文自带的五项评分量表。目录分别归入 70/78/72/25/53 项，共 298 项；目录数不代表测量或评分覆盖。已有数值仅是工程子项过程参考，不能充当完整维度技术分；缺少数值时不绘制默认分数。动作衔接保留独立观测，不混合分数。

俯视图优先使用逐帧有效场地标定的球路地面投影，不能当作真实落点。未标定视频可在「球场设置」从原视频当前帧取图，按远左、远右、近右、近左点选四个双打外角，并确认固定机位；该标定只在当前页面用于展示，不参与评分，不跨任务复用。未标定时不把画面坐标冒充场地坐标。

逐项判定保留原文版本与校验、指标状态、计算方法、缺少依据及实测值。局部连续片段与完整阶段分开显示，数值为空但局部窗口有效的观测仍可查看；代表性抽样同时展示返回条数和完整接收条数。过程契约 v1.1 兼容 v1.0 历史报告，区分规则待标定、独立目标参照缺失及触球控制尚未实现；已有步伐观测可独立查看，不能因方向子项缺目标而隐藏。Markdown、HTML 和 JSON 导出均保留五维说明、原文目录来源、298 项状态以及局部测量，衔接的独立过程记录继续保留。

标注工作台独立位于 `/annotate`，使用同一域名和 Cloudflare 隧道。训练空间右上角“更多工具”中的“标注工作台”会在新标签页打开；从实际任务报告进入时自动携带 `?job=任务编号`。也可以在标注页粘贴任务编号或本站报告链接，或选择当前浏览器的最近报告。标注页加载已完成任务，集中提供视频回放、原文标准、人工等级/观察记录、保存修订和评审导出；标注记录仍由原有后端接口保存。导入的离线报告不会自动当作可写入的服务端任务。

页面地址使用 `?view=overview|sessions|analysis|guide`，旧 `?job=...` 报告链接继续有效。首页不会因为浏览器保留旧任务编号而自动跳回报告。训练记录支持搜索、修改名称、主题与备注、保存关注点，以及在新分析前选择上次的问题。记录和关注点仅保存在当前浏览器，不保存视频、不跨设备同步；旧最近访问列表会兼容保留。日期表示最近查看时间，不冒充视频拍摄时间。前后片段只有在时间映射有效时提供定位，不自动宣称技术进步。改版早期范围见 [前端产品改版说明](../docs/前端产品改版说明_2026-10-04.md)。

上传、服务器分析、报告读取、部分结果、完成、取消、失败和记录不存在分别展示；服务器历史耗时与本次浏览器等待时间分开。主结果先到时即可查看，补充证据继续读取；整理阶段不显示虚假的 100%。离线备份只读本地报告，不根据其中的任务编号加载在线视频、姿态或问答；原片缺失时明确提示不可回放。

公网根地址 `/` 默认跳转到品牌宣传页 `/welcome`，包含原创网球主视觉、可拖动的复盘交互示意、三步流程与常见问题；“开始体验”进入 `/?view=analysis`，已有 `?view=...` 和 `?job=...` 链接保持原有去向。设计参考、素材生成提示词与验收记录见 [宣传页设计与素材](../docs/宣传页设计与素材_2026-10-04.md)。

## 本机启动

先从仓库根目录启动 Python 分析服务，详情见根 README，再运行 `npm ci`、`npm run dev`。浏览器访问终端打印的地址（默认 localhost:3000）。Vite 将 /v1 与 /health 转发到本机 8000 端口。

在本目录新建 `.dev.vars`（已被 Git 忽略），仅放服务端配置：

```dotenv
RALLYMATE_API_ORIGIN=http://127.0.0.1:8000
RALLYMATE_API_KEY=
MIMO_ADVICE_ENABLED=0
MIMO_API_KEY=
MIMO_PROVIDER=openai
MIMO_MODEL=mimo-v2.5-pro
MIMO_BASE_URL=https://api.xiaomimimo.com/v1
```

填入分析服务配置后重启开发服务。Vite 上传代理与 Worker 建议服务共用 `.dev.vars` 中的分析地址和密钥；进程环境变量可覆盖代理设置。不要把这些值放到任何公开变量中。

MiMo 默认不调用；识别依据与补充拍摄建议由服务端生成。真实调用必须显式设置 `MIMO_ADVICE_ENABLED=1` 并使用官方按量 API 密钥。Anthropic 兼容模式使用 `MIMO_PROVIDER=anthropic`、`MIMO_BASE_URL=https://api.xiaomimimo.com/anthropic`。接口地址仅接受这两个精确的官方配置，不接受自定义反代地址、Token Plan 密钥或套餐端点。

[小米接入文档](https://mimo.mi.com/docs/en-US/quick-start/summary/first-api-call)区分了按量 API 与套餐凭据；[Token Plan 规则](https://mimo.mi.com/docs/zh-CN/tokenplan/Token%20Plan/subscription)限制自定义应用后端等非编程用途。切换反代不能改变套餐使用范围。公网付费调用启用前，须完成[反代与额度方案](../deploy/autodl/MIMO_PROXY_PLAN.md)中的匿名任务授权、持久配额和预算保护；这些保护目前仍是实施计划，不要仅填写新密钥就对公网启用。

## 访问与建议防护

- `/api/advice` 接收主题、水平、目标、最多 600 字问题与可选 jobId。
- 从固定分析服务读取并核对 jobId，只使用所选动作类别的证据；步伐结果不能支持底线或接发评价。
- 无视频、分析读取失败、该类动作证据不足时直接返回明确说明与补证步骤，不调用 MiMo，不猜动作错误原因。
- 只有二维运动时明确标注规则推断、触球未确认及缺失阶段；部分片段不能拼成完整动作。模型关闭或异常与识别不足分别展示。
- 有可用证据时只发送压缩后的该类事实和问题，不向 MiMo 发送视频、帧或模型文件。
- 每实例并发上限 2、每来源 10 分钟 5 次；请求 8 KB、模型响应 64 KB、超时 25 秒。
- 模型只选择已有事实与批准建议的编号；展示文字由服务端生成，拒绝自由诊断、编造事实或新增训练方法。
- 输入注入、未知字段、异常输出与身体不适均有独立处理。进程限流不能代替云端 WAF 或多实例持久配额。

## 云端 Worker

在 Worker 的服务端 Secrets 中配置 `RALLYMATE_API_ORIGIN`（可达的 HTTPS 分析服务）、`RALLYMATE_API_KEY`。MiMo 保持默认关闭，启用条件见上文。网站访问无需账号或密码；分析服务与模型密钥仍仅保存在服务端。独立部署的 Worker 不得把 localhost 配成云端分析地址。

Worker 仅代理明确列出的任务、结果、媒体与健康路径；隔离浏览器 Cookie/Authorization，支持媒体 Range、超时和明确错误。持有网站链接即可上传、推理及查看对应任务结果。自行托管的 Nginx 方案见 `../deploy/README.md`。

## 本机生产模式验收

```bash
npm run build
node --env-file=.dev.vars node_modules/vinext/dist/cli.js start --port 3001 --hostname 127.0.0.1
```

此模式直接运行构建产物，通过 Worker 的代理读取分析服务，不依赖 Vite 开发代理。线上使用 Node.js 22.13 或更高版本，并由进程管理器注入 Secrets，不能携带本机 `.dev.vars` 发布。

若前端、Python 分析服务与 `cloudflared` 同在 AutoDL 等服务器上，配置 `RALLYMATE_API_ORIGIN=http://127.0.0.1:8000`、`RALLYMATE_LOCAL_TUNNEL=1`，使 Cloudflare HTTPS 入口能通过前端访问回环分析服务。保留 `RALLYMATE_API_KEY` 与后端配置一致。启动前端后运行 `cloudflared tunnel --url http://127.0.0.1:3001`，浏览器通过隧道地址免登录访问；上传请求仍限定同源。
