# MiMo 建议服务：反代与证据说明方案

更新：2026-09-24。范围：现有网球项目的 `/api/advice`。用户授权后，基础防护与证据解释已部署到 AutoDL，发布编号 `20260924T130527Z`；云端明确设置 `MIMO_ADVICE_ENABLED=0`，未启用付费调用。网站继续免账号密码访问。匿名任务授权与持久预算仍是后续计划。

## 核查结论

现有接口不是任意 URL 转发器：客户端不能提交上游地址、模型密钥或任意 messages；消息由服务端组装，上游重定向不会自动跟随。当前没有发现密钥已泄漏或有人正在盗刷的证据。

实质缺口在于公开业务接口的付费保护。现有每来源 10 分钟 5 次、每进程并发 2 的内存限制，会随重启清空，也不能覆盖多个实例或分散来源。Origin/Sec-Fetch-Site 校验只能辅助防止浏览器跨站调用，不能认证脚本调用者。`cf-connecting-ip` 仅在确保请求由 Cloudflare 进入时可信，不能用任意客户端提供的头替代身份。

本机 `.dev.vars` 只做了脱敏类型检查：已配置的是 Token Plan 类型凭据；原代码默认也是套餐端点。没有输出凭据；发布仅在服务端保留受限权限的原配置备份并设置关闭标志，未更换模型密钥。未核对云端 MiMo 凭据类型，不能据此断言云端使用同一类型。[小米官方规则](https://mimo.mi.com/docs/zh-CN/tokenplan/Token%20Plan/subscription)将套餐限定于编程工具场景，并禁止自动脚本、自定义应用后端等非编程用途。网球网站应使用单独的按量 API 凭据。更换反代、隐藏来源或轮换账号不改变使用范围。

另一个已确认问题是建议上下文混用了不同动作的证据；没有所选类别的有效识别时，也可能请求语言模型。这样容易让通用提示看起来像对当前视频的诊断。

## 本轮已实现并部署

- `MIMO_ADVICE_ENABLED` 默认关闭；仅显式 `1` 才可能调用上游，已有密钥本身不能开启付费功能。
- 固定官方按量地址：OpenAI 兼容为 `https://api.xiaomimimo.com/v1`；Anthropic 兼容为 `https://api.xiaomimimo.com/anthropic`。配置与请求地址严格匹配，拒绝自定义反代域名、端口、userinfo、查询串、片段、路径变体、Token Plan 凭据与套餐地址。参见[官方接入说明](https://mimo.mi.com/docs/en-US/quick-start/summary/first-api-call)。
- 按 jobId 核对结果，按底线、发球、接发、网前、步伐分别取证；其他类别的分数不能支持当前动作评价。
- 无视频、分析不可用、该类证据不足时不调用 MiMo，直接给出明确的识别说明和补证步骤。
- 仅有二维运动时保留规则推断、触球未确认和缺失阶段信息，不将不同片段的阶段拼成完整动作。
- 有证据时，模型只能选择服务端已核验事实与建议的编号；展示文字由服务端生成。没有自由诊断、分数或新增训练方法的输出通道。
- 前端展示可确认内容、尚不能判断的部分、补充步骤。切换任务或动作类别后，不显示上一上下文的建议。

匿名任务凭证、持久额度、预算熔断和 Turnstile **尚未实现**。以下是公开启用付费服务前的实施计划，不是现有能力。

## 建议的请求路径

```text
浏览器（免登录）
  → 固定 HTTPS 域名 / Cloudflare
  → AutoDL 上的 cloudflared 出站隧道
  → 仅监听 127.0.0.1 的 Web 业务接口
  → 私有建议模块：任务授权 → 查证据 → 查缓存 → 原子预留预算
  → 固定的 MiMo 官方按量 API
```

Cloudflare 隧道负责网站入口，MiMo 调用由 AutoDL 服务端直接发往官方接口；浏览器不接触 MiMo 密钥。不提供公开 `/v1/chat/completions`、`/anthropic/*` 或通用 URL 转发功能。

保留现有精确路径白名单。Nginx 示例当前宽泛的 `/v1/` 转发需在正式采用前收窄，或统一转给业务网关，避免未来后端新增管理接口时被自动公开。API、Web 的原始端口只监听回环地址，不允许绕过入口直接访问；密钥不进入 `NEXT_PUBLIC_*`、HTML、脚本或日志。不要把浏览器 Cookie、Authorization 或任意自定义头转发给 MiMo，只在服务端生成必要的固定上游头。保持 TLS 校验和禁止重定向，不因上游连接问题改成未知中转。

## 免登录下的授权边界

1. 上传创建时生成随机匿名会话，使用 `HttpOnly; Secure; SameSite=Lax` Cookie。服务端保存会话与所创建任务的对应关系，不能只信任客户端传入的 jobId。
2. 建议请求使用短期签名凭证，绑定会话、jobId、允许操作 `advice`、到期时间和 nonce；有原子防重放记录。凭证不能放入可分享 URL 或 LocalStorage。CSRF 采用同源校验与会话绑定 token，不能把 Origin 当用户身份。
3. “分享查看结果”与“调用付费建议”是独立权限。公开结果链接不能兑换付费建议凭证。匿名会话只是有限的防滥用措施，不代表可靠的真人身份。
4. 旧任务没有归属信息时，继续提供只读回放和确定性的证据说明。不能采用“谁先拿到公开 jobId 谁就获得所有权”；付费授权需由明确的服务端迁移规则、所有者授予，或重新上传时建立。
5. 新会话可被批量创建，因此会话配额必须与全局预算、任务配额共同使用。清除 Cookie 不能重置全局预算。

## 持久额度与失败处理

单 AutoDL 实例可使用私有 SQLite 账本；多实例必须共享同一账本服务。若以后迁往 Cloudflare Worker，应使用具备原子串行化能力的共享服务，例如 Durable Object，不能把独立进程 Map 当总额度。

账本记录：会话摘要、任务、请求 nonce、证据版本、预留 token、实际 usage、状态、并发租约与时间。密钥和用户完整问题不写入账本或应用日志。调用顺序：

1. 验证输入、会话与任务权限；读取当前类别的有效证据。无效时返回确定性说明，不占用付费额度。
2. 查询缓存：按任务、动作类别、证据/算法版本、提示版本、模型与问题的 HMAC 摘要隔离；先授权后取缓存。禁止跨任务复用个性化结果。
3. 事务内检查每会话、每任务、全局每日硬上限及并发租约，预留本次最坏 token 消耗，提交后才发起请求。一个实例重启不能清空用量；日界线统一用 UTC 并明确展示。
4. 上游成功后以 usage 结算；请求超时、断线、未知处理状态时保留保守预留，等待对账，不能直接退款后无限重试。nonce 去重，默认不自动重复有计费可能的请求。
5. 超额返回 `429` 和 `Retry-After`；预算耗尽或人工关闭时停止上游调用，继续提供本地证据说明。定时回收过期并发租约不等于退还未知费用。

现有并发 2、每来源 5 次/10 分钟可作为初始候选参数。每任务上限、全局每日金额/token 上限需要在启用前明确配置；未配置硬上限应保持关闭，不推定用户已经批准任何金额。配置变更也不能让账本余额消失。上游平台如提供账户预算限制，应同时设置，但不能代替项目自己的账本。

## Cloudflare 与匿名防刷

正式入口建议改为自有固定域名与受管理的命名隧道，便于固定 Origin、Cookie 与验证配置。[Quick Tunnel 官方说明](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/)将随机域名定位于测试开发、不提供运行 SLA，且有 200 个在途请求限制。当前随机域名仍可用于演示，不能把地址不公开当成安全边界。

在拥有域名和相应配置权限后，可对建议请求增加 Turnstile、边缘限流；后端仍必须执行会话授权和预算检查。[Turnstile 文档](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)要求服务端 Siteverify，token 五分钟有效且单次使用；校验预期 hostname/action，禁止验证失败后降级放行。Turnstile 证明一次挑战结果，不证明任务归属，也不代替付费额度。

## 未有效识别时如何解释

- **无视频**：“当前未关联视频分析，无法评价这次接发。请先上传并完成分析。”用户文字只作为自述。
- **服务读取失败**：“当前无法读取接发分析，暂时无法评价该动作。请稍后重试或保留任务编号排查。”不把服务异常解释为拍摄差或动作差。
- **任务完成但接发证据不足**：“当前视频尚未得到可用于评价接发的有效识别。未识别不代表没有该动作，也不代表动作有问题。”补充对手发球、来球和接球者的连续画面，是获取证据的建议，不是本次失败原因。
- **仅有挥拍测量**：“已获得两段发球相关的二维运动测量；阶段为规则估计，球拍触球未确认。可回放核对已测到的部分，不能据此判定触球时机或动作质量。”
- **部分阶段缺失**：明确哪些阶段缺证，不能给出“完整准备—加速—随挥都已识别”的结论，不将片段合并为一次完整动作。
- **语言模型关闭/故障**：单独说明建议服务状态；已有视频识别依据仍展示，不能声称已生成个性化指导。

这里的“有效事件”仍不自动等于确认触球、准确率或技术评分。低覆盖率不是准确率，候选也不能转为确认次数。

## 实施与验收顺序

第一阶段（本轮本地）：证据隔离、明确解释、官方上游白名单、默认关闭、配置示例与测试。真实云端结果只读核对：30 秒发球任务为两段二维运动；长视频底线为部分阶段；接发均证据不足。没有真实请求 MiMo。

验证结果：前端完整构建、103 项测试、TypeScript 检查与 ESLint 通过。本机生产模式浏览器实测无视频时显示明确的证据缺失说明，切换接发至发球后旧建议清除；解释卡片布局已检查。

服务器部署验证：暂存目录重新构建、类型检查、38 项针对测试通过，18 个发布文件哈希核对一致，仅重启 Web。公网首页免登录；无视频、发球二维运动、接发证据不足三个分支均 HTTP 200，发球明确返回 providerStatus=disabled。浏览器实测接发解释和补证步骤正常，未调用真实 MiMo。

第二阶段（待实现）：会话/任务授权、共享账本、缓存、原子预算与幂等。验证更换会话、重启、多实例竞争、超时和并发时都不能绕过全局额度；公开 jobId 不能获得付费权限。确定固定域名和按量密钥的安全注入方式。

第三阶段（基础版已部署，付费启用待完成）：已在无运行/排队推理任务时发布经过验证的指定文件，provider 保持关闭。完成第二阶段后，按配置的预算和启用条件做一次有限真实调用验证，才可开启公网付费功能。不要打包本机 `.dev.vars`、凭据或所有未提交改动。

验收必须覆盖：任意 URL/消息/模型参数拒绝、重定向不跟随、跨任务授权拒绝、伪造 IP 不扩大全局额度、重复 nonce 不重复计费、无结果不调用模型、步伐不能支持接发、部分阶段不拼接、模型非法输出回退、切换任务不残留建议，以及密钥不进入页面或日志。

监控仅统计请求量、缓存命中、拒绝原因、延迟、上游状态、预留/实用 token 和预算余量，不记录密钥、视频、完整问题或上游原始错误体。关闭开关即可回滚到确定性证据说明，视频推理和回放继续可用；不要在回滚中删除额度账本。
