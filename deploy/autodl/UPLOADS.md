# 视频上传、续传与推理流程

网页把文件按原始字节切成 **4 MiB** 的分块，最多 **2 块并发**上传。56.7 MiB 的视频需要 15 块。这些分块不是可独立播放的视频片段，也不会分别做推理，因此不会在块边界丢失发球的连续动作。

1. `POST /v1/uploads` 建立持久会话，提交文件名、字节数、分析选项和随机会话 ID。创建阶段检查格式、范围与磁盘空间。
2. 浏览器保存会话 ID，服务器返回已确认的分块及 SHA-256。恢复时核对每个已有分块与本次所选文件的内容；仅文件名、大小相同不能作为复用依据。
3. `PUT /v1/uploads/{id}/chunks/{index}` 发送原始字节及 SHA-256。服务器限制块长度、检查内容校验和，原子保存；同一块重复提交不重复计算进度。暂时网络错误按退避自动重试。
4. `POST /v1/uploads/{id}/complete` 在跨进程锁内检查所有块，按序合并并再次核验完整长度，然后解码检查视频，写入持久 SQLite 队列。创建任务使用会话 ID；即使响应丢失、API 重启或同时点两次完成，也只返回同一任务。
5. GPU Worker 读取完整视频做连续帧分析。网页轮询任务进度，可关闭再打开继续读取；短暂断线不终止服务器推理。

页面显示服务器实际确认的字节数、百分比与平均上传速度。上传、校验合并、排队、推理分别显示，不再用固定 18% 代表上传进度。速度仍取决于手机网络、到 Cloudflare 的线路及云端带宽，分块主要减少失败重传代价。

未完成的分块保留 **24 小时**。再次选择相同文件并点击“继续上传”会补齐缺块。刷新页面或重新打开浏览器后，需要重新选择本地文件（浏览器不会永久授予文件读取权限）。会话 ID 保存在当前网站的本地存储中；更换浏览器、清除存储或 Cloudflare 随机域名改变后，无法自动找回旧会话。云端定期清理过期分块，已提交任务的原始视频和报告不受影响。

服务器为暂存块、合并文件和持久视频预留空间。单块内存有上限，合并按块顺序执行；不把整个大视频放进 API 内存。已完成任务保留 manifest 以保障重复完成的幂等返回。

原来的 `POST /v1/jobs` 保留给已有接口使用。它仍是一次性 multipart 上传；网页已切换到上述续传协议。后端原先 `video.read(1024 * 1024)` 的 1 MiB 读取只控制磁盘写入缓冲，并不意味着浏览器已有可恢复上传。

Cloudflare Quick Tunnel 可从 AutoDL 直接建立出站连接，但域名随隧道重启变化，且服务定位是测试用途；正式长期访问宜使用固定域名的命名隧道。参见 [Cloudflare Quick Tunnels 官方说明](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/)。本次服务升级不重启隧道，保留已有地址。
